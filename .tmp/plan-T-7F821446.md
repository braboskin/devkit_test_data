# План S2b: Календарь Apple Calendar

## Контекст

- Каркас S0 и бэкенд S1 в `main`; текущий `pages/calendar` — рукописный грид без
  видов и сайдбара.
- ТЗ §6.3 (Год/Месяц/Неделя/День/Agenda, сайдбар календарей, поповер события,
  drag/resize, повторы с областью), §9 (FullCalendar 6.1.22 пинован, год —
  `@fullcalendar/multimonth` или свой грид), Acceptance A7.
- API: `/api/events` (CRUD, `rrule`, `remind_minutes`, участники), `/api/spheres`
  (цвет интереса), `/api/people` (участники). Зависимости уже в
  `package.json` — новые не добавлять.

## Шаги

1. Спайк года в первый день: `@fullcalendar/multimonth` против своего грида
   (12 мини-месяцев). Решение зафиксировать в плане задачи.
2. `shared/ui/calendar.tsx`: обёртка FullCalendar с локализацией `ru`, скином
   под токены, обработчиками select/eventDrop/eventResize/eventClick.
3. `pages/calendar`: шапка (вид Год/Месяц/Неделя/День/Agenda, «Сегодня»,
   prev/next, поиск по событиям), левый сайдбар (мини-месяц, календари-интересы
   с цветом и чекбоксом), основная область, мобильная раскладка (Год 3×4,
   Месяц + список дня, Неделя — лента дней, FAB «+»).
4. Поповер события: название, время, интерес/проект, место, заметка, участники,
   RRULE, напоминание, «Изменить/Удалить/Открыть задачу». Для повторяющихся —
   вопрос «это / это и будущие / все» (в v1 — правка/удаление серии целиком, если
   API не умеет исключения; честно указать в отчёте).
5. Вид и дата в URL (`/calendar?view=month&date=YYYY-MM-DD`), состояние
   календарей — localStorage.
6. Создание: клик по дню/протяжка → форма события (`POST /api/events`),
   перенос/resize — `PATCH`.
7. Доступность: клавиатура по сетке, Esc закрывает поповер, фокус видим.
8. Проверки и отчёт.

## Acceptance

- Пять видов переключаются, листание по своей гранулярности, «Сегодня».
- Сайдбар скрывает/показывает календари интересов; цвет совпадает с интересом.
- Создание, перенос, resize и удаление события работают и сохраняются после
  перезагрузки.
- Повторяющееся событие отображается по RRULE, при правке понятно, что меняется.
- Мобильный: виды пригодны, ничего не уезжает, таргеты ≥ 44px.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web` — с exit code в отчёт.

## Scope

`viewer/src/pages/calendar`, `viewer/src/shared/ui/calendar.tsx`,
`viewer/src/app/router.tsx` (только строка маршрута при необходимости). Бэкенд,
`package.json`, другие экраны — не трогать.

## Риски

- **Год-вид**: если `multimonth` не даёт Apple-вид — свой грид (12 мини-месяцев),
  остальные виды на FullCalendar.
- **RRULE-серии**: FullCalendar не раскрывает серию в исключения; если API не
  поддерживает EXDATE, правка серии — только вся серия, это ограничение в отчёт.
- **Время**: события хранятся настенным временем (naive); FullCalendar работает в
  локальной зоне — проверить границу суток и all-day.
- **Скин**: FullCalendar CSS + токены; проверить тёмную тему и стекло шапки.
