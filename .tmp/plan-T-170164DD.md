# План S2e: Чат и настройки агентов

## Контекст

- `pages/chat` (M3) и `pages/agents` работают, но собраны на нативном HTML и не
  переведены на дизайн-систему; API менять не нужно: `/api/chats`,
  `/api/chats/{id}/messages` (SSE), `/api/proposals`, `/api/agents`.
- ТЗ §6.2 и §6.15; Acceptance A1 (шестерёнка к агентам), A8 (мобильный переход
  список→тред).

## Шаги

1. `pages/chat`: двухпанельный чат (список 280px + тред, на мобильном —
   список → тред с back), поиск по чатам, «Новый чат».
2. Тред: сообщения, чипы источников (клик → документ), индикатор инструментов,
   «Стоп», переключатель «Глубокий анализ», композер с вложением; ошибки/пустое
   состояние через `Alert`/`EmptyState`.
3. Заголовок треда: модель и шестерёнка → `/settings/agents`.
4. `pages/agents`: список агентов, вкл/выкл, редактирование промпта, последние
   запуски — на `Card`/`Tabs`/`TextField`/`Button`.
5. Мобильный: композер липкий с safe-area, тред без нижних табов.
6. Проверки и отчёт.

## Acceptance

- Чат работает как раньше: сообщения, стриминг, источники, стоп, глубокий
  анализ; вложения.
- Шестерёнка открывает настройки агентов; изменения агента сохраняются.
- Мобильный: список → тред → назад, композер с safe-area.
- Прямых импортов antd в страницах нет.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web` — с exit
code в отчёт; сценарий чата войдёт в e2e в S4.

## Scope

`viewer/src/pages/{chat,agents}`. Бэкенд не меняется.

## Риски

- **SSE-поток**: не менять обработчики и тайминги; рефакторить только разметку.
- **Состояние чата** (активный чат в URL) — сохранить deep link `/chat/:id`.
- **Длинные сообщения/вложения**: не переводить на виртуализацию в этой
  задаче; следить за мобильной прокруткой.
