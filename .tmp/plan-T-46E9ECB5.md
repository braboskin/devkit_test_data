# План: Файлы — серверные фильтры и пагинация

## Контекст

`GET /api/documents` отдаёт все документы, `pages/files` грузит их целиком и
группирует на клиенте. При тысячах файлов это медленно. Нужны фильтры и
постраничная загрузка без смены формы ответа (массив), чтобы не ломать
существующие тесты/клиентов.

## Шаги

1. `features/documents/repository.py`: выборка с фильтрами `sphere_id`,
   `project_id`, `status`, поиском `q` (ILIKE по title) и `limit/offset`
   (ownership сохраняется как сейчас).
2. `features/documents/router.py`: query-параметры, валидация (`limit ≤ 200`,
   `offset ≥ 0`), тот же ответ — массив `DocumentItem`.
3. `viewer/src/pages/files`: фильтры «сфера», «статус», строка поиска в URL
   (`?sphere=&status=&q=`), «Показать ещё» (offset += limit), сохранение
   группировки дерева по загруженным данным; пустое состояние «ничего не
   найдено».
4. Тесты: API фильтров/пагинации и ownership; web-тест не ослабляем.

## Acceptance

- Фильтры сферы/статуса/поиска и пагинация работают, состояние в URL.
- Ответ прежней формы (массив), лимит по умолчанию 100.
- Ownership: чужие документы не видны ни с какими фильтрами.
- Проверки профиля зелёные.

## Проверки

`unit-tests`, `lint-python`, `typecheck-python`, `arch-python`,
`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web`.

## Scope

`app/features/documents`, `viewer/src/pages/files`, `viewer/src/shared/api`,
`tests/test_documents*.py` (при необходимости).

## Риски

- Пагинация несовместима с деревом «всё сразу»: грузим страницами и
  группируем загруженное; полное дерево — только с серверной агрегацией
  (follow-up).
- ILIKE на SQLite регистронезависим только для ASCII — известное ограничение.
