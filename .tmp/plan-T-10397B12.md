# План: Гант — drag/resize задач

## Контекст

`shared/ui/gantt.tsx` рендерит SVAR Gantt в режиме `readonly`. Нужно
перетаскивание задач (сдвиг дат) и изменение длительности с записью
`start_at`/`due_at`, с валидацией и откатом при ошибке.

## Шаги

1. Убрать `readonly`, включить редактирование дат в SVAR (props/события
   изменения задачи); проверить API по типам пакета.
2. `TaskGantt` получает `onChange(id, {start_at, due_at})`; преобразование
   дат (Date ↔ ISO, настенное время) в одном месте.
3. `ProjectPage`: PATCH `/api/tasks/{id}` с новыми датами; оптимистичного
   обновления нет — после успеха `tasks.reload()`, при ошибке — тоже reload
   (откат) и `Alert`.
4. Отключить drag для задач без `start_at`/`due_at` (гонт их не рисует).
5. Ручная проверка на стенде + существующие e2e (проект открывается, чанк
   грузится) не ломаем.

## Acceptance

- Перетаскивание меняет `start_at`/`due_at` на сервере; после ошибки даты
  возвращаются.
- Задачи без дат не участвуют в drag.
- Проверки профиля зелёные.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web`,
`e2e`, `a11y`.

## Scope

`viewer/src/shared/ui/gantt.tsx`, `viewer/src/pages/projects`.

## Риски

- SVAR может требовать `history`/editor для drag — проверяем по типам; если
  drag недоступен без PRO, фиксируем ограничение и делаем custom-handle
  (эскалация, не тихая подмена).
- Настенное время: даты задач хранятся в wall-clock, преобразование — как у
  календаря.
- Гант может дёргать события при программном изменении данных — игнорируем
  изменения без отличий.
