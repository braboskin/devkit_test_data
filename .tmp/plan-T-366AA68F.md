# План S3: Проект — дерево, доска, гант; экран Задачи

## Контекст

- S0–S2 в `main`: каркас, бэкенд (start_at/progress задач, summary), экраны,
  календарь, файлы. SVAR Kanban 2.7.0 и SVAR Gantt 2.8.3 уже установлены (S0),
  новых зависимостей не нужно.
- Детальный экран проекта сейчас — временная карточка в `pages/projects`
  (summary + список задач). API: `/api/tasks` (start_at, progress, due_at,
  status, project_id), зависимости — `blocked_by` в карточке задачи
  (`GET /api/tasks/{id}`).
- ТЗ §6.7–6.8, §9 (PRO-фичи SVAR не покупаем), Acceptance A6.
- Ограничение Steiger: слой `pages` уже на лимите 20 слайсов, поэтому новый
  слайс `pages/project` не создаём — деталь проекта живёт в `pages/projects`.

## Шаги

1. **Спайк SVAR** (первый день): подтвердить API Kanban (`cards`, `columns`,
   `onMove`/API) и Gantt (`tasks` c `start/end/progress`, `links`), импорт
   `all.css`, поведение тем. Результат — коротко в отчёте.
2. `shared/ui/board.tsx`: обёртка Kanban — колонки `todo/doing/done`, карточки
   из задач (title, priority, due), drag между колонками → `PATCH
   /api/tasks/{id}` (status), перезагрузка/оптимистичное обновление, свои
   шаблоны карточек.
3. `shared/ui/gantt.tsx`: обёртка Gantt — `start_at`→`start`, `due_at`→`end`,
   `progress`, подзадачи (`parent_id`) как иерархия; зависимости из
   `blocked_by` (карточки задач, N запросов на проект — приемлемо для ≤50
   задач, отмечено в отчёте), без редактирования drag (только просмотр) в v1.
4. `pages/projects`: ProjectPage получает переключатель представлений
   «Список · Доска · Гант» с видом в URL (`?view=tree|board|gantt`):
   - Список — группировка по статусу/приоритету, свёртка, поиск, фильтры.
   - Доска — `shared/ui/board`.
   - Гант — `shared/ui/gantt`.
   Шапка проекта: прогресс (summary), даты, ссылка на сферу.
5. `pages/tasks`: дефолтный фильтр «Без сферы и проекта» из URL
   (`/tasks?filter=unassigned`), фильтры «Все/Без сферы и проекта», группировка
   по статусу, быстрый переход в проект; мобильный — компактный список.
6. Мобильный: доска — горизонтальный скролл колонок, гант — горизонтальный
   скролл с липкой левой колонкой (средствами SVAR), дерево — свёртка.
7. Проверки профиля и отчёт; CSS SVAR водится токенами (тёмная тема).

## Acceptance

- В проекте работают три представления, выбор сохраняется в URL и переживает
  перезагрузку.
- Доска: карточки по статусам, drag меняет статус на сервере, откат при ошибке.
- Гант: полосы от start до due, прогресс, подзадачи, зависимости видны.
- Экран «Задачи» открывается с фильтром «Без сферы и проекта» и показывает
  задачи без сферы/проекта; фильтр «Все» возвращает все.
- Новых зависимостей нет; PRO-функции не используются.
- Проверки профиля зелёные, Steiger без новых ошибок.

`web-build`, `typecheck-web`, `lint-web`, `arch-web` — с exit code в отчёт.

## Риски

- **SVAR API** может отличаться от README (v2.7/2.8): спайк до основной работы;
  если Kanban/Gantt не заводятся в React 19 — эскалация с выбором fallback
  (своя доска/гант), а не тихая подмена.
- **N+1 зависимостей** на ганте: для больших проектов нужен bulk-эндпоинт
  `GET /api/tasks/dependencies?project_id=` — отдельной задачей бэкенда.
- **Вес бандла** вырастет ещё (SVAR CSS+JS) — ленивая загрузка представлений
  (`React.lazy`) как мера.
- **CSS SVAR** глобальный: проверить, что не ломает остальные экраны.
- **Steiger-лимит слайсов**: новые экраны не добавляем, расширяем существующие.
