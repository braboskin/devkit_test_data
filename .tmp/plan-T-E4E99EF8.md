# План: Уведомления — автообновление списка и счётчика

## Контекст

`pages/notifications` обновляется только при заходе; бейдж в шапке
(`AppShell`) запрашивает счётчик один раз при монтировании. Нужен периодический
опрос без лишней нагрузки на скрытой вкладке.

## Шаги

1. `pages/notifications`: интервал 15 с (`POLL_MS`), `setInterval` /
   `clearInterval`, пауза при `document.hidden` (visibilitychange), ошибка
   опроса не сбрасывает уже показанный список.
2. `AppShell`: обновлять `unread_count` тем же интервалом в 30 с, только когда
   вкладка видима; событие `atlas:notifications` из страницы уведомлений
   немедленно обновляет бейдж (прочитать → счётчик меняется сразу).
3. Не дублировать запросы: один таймер на компонент, очистка на размонтировании.
4. Проверка: web-тест (grep по `setInterval`/`clearInterval`/`POLL_MS` в
   `Notifications.tsx` и `AppShell.tsx`), e2e существующие не ломаем.

## Acceptance

- Список и бейдж обновляются автоматически, на скрытой вкладке опрос
  останавливается.
- Прочтение уведомления немедленно меняет счётчик в шапке.
- Таймеры очищаются при размонтировании.
- Проверки профиля зелёные.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web`,
`e2e`, `a11y`.

## Scope

`viewer/src/pages/notifications`, `viewer/src/app/AppShell.tsx`,
`tests/test_web_build.py` (если нужно расширить проверку).

## Риски

- Много вкладок × интервал = лишние запросы; смягчаем visibility API.
- Бейдж не должен мигать при ошибке сети — при неудаче оставляем прежнее
  значение.
