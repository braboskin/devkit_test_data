# План T-59D31937 — роутинг: SPA-fallback и страница 404

## Контекст

- `app/backend/main.py` (конец `create_app`): при наличии `viewer/dist/index.html`
  монтируется `StaticFiles(directory=dist, html=True)` на `/`. Для
  `GET /settings` файла нет → Starlette отдаёт **404 JSON**, поэтому любой deep
  link, кроме `/`, умирает на собранном фронте. В dev-режиме это маскирует Vite.
- `viewer/src/app/router.tsx`: wildcard `{ path: '*', element: <Navigate to="/" /> }`
  и легаси-редиректы (`today`, `documents`, `interests`) уже есть; `router` —
  `createBrowserRouter`, есть lazy-маршруты (`/calendar`, `/projects/:id`).
- `tests/test_app_auth.py::test_root_json_without_viewer_build` ожидает JSON на
  `/`, когда `viewer/dist` не собран; `tests/test_web_build.py` пропускается без
  сборки. E2E: `e2e/shell.spec.ts` (`page.goto('/calendar')`), `e2e/a11y.spec.ts`
  на 5 маршрутах, `e2e/mockApi.ts` перехватывает `/api/**`.
- FSD: новый экран — новый слайс `pages/not-found/` (Steiger), публичный API
  через `index.ts`.
- antd-first (ТЗ R1.9): 404 внутри оболочки — `Result status="404"`.

## Шаги

1. **Бэкенд.** В `app/backend/main.py` — класс `SPAStaticFiles(StaticFiles)`:
   `get_response` сначала пробует `super()`, при `HTTPException(404)` и пути вне
   `/api/**` и `/health` возвращает `index.html`; для `/api/**` и `/health`
   пробрасывает 404 как есть (JSON, а не HTML). Монтирование — как сейчас, имя
   `viewer` (переименует T-EAD5B055).
2. **Слайс 404.** `pages/not-found/{index.ts,ui/NotFound.tsx}`: antd `Result`
   `status="404"`, заголовок «Страница не найдена», показанный `pathname`
   (из `useLocation`), кнопка «На главную» (`Button` + `useNavigate('/')`).
3. **Роутер.** Заменить wildcard на `<NotFound />`; легаси-редиректы сохранить;
   `createBrowserRouter` и lazy-границы не трогать.
4. **Тесты бэкенда.** Новый `tests/test_spa_fallback.py` (класс
   `SpaFallbackTests`): если `viewer/dist/index.html` нет — `skipTest` с
   сообщением про сборку; иначе: `GET /settings` → 200, `text/html`, есть
   `<div id="root">`; `GET /nope` → 200 HTML; `GET /api/nope` → 404 JSON
   (`detail` в теле); `GET /health` → 200 JSON.
5. **E2E.** `e2e/not-found.spec.ts`: `goto('/nope')` → виден заголовок «Страница
   не найдена» и путь `/nope`; клик «На главную» ведёт на `/`; проверка, что
   после клика нет 404-страницы. `mockApi` не меняется.
6. **Проверки.** Профиль + e2e + a11y; зафиксировать в отчёте, что известный
   баг deep link воспроизведён до правки (curl на собранном фронте) и исчез
   после.

## Acceptance

- A8: на собранном фронте `GET /settings`, `/chat/1`, `/nope` отдают SPA-
  оболочку; `GET /api/nope` — JSON 404; `/nope` показывает страницу 404 с
  кнопкой «На главную».
- Легаси-редиректы (`/today`, `/documents`, `/interests`) работают как раньше.
- `/health` и неизвестные `/api/**` не подменяются HTML.
- `test_app_auth`, `test_web_build` и остальные существующие тесты не ослаблены.
- axe: новых нарушений нет (404-страница проходит тот же аудит).

## Риски

1. **Порядок монтирования.** `StaticFiles` смонтирован после всех роутеров —
   `/api/**` попадают в свои роутеры; проверяем, что неизвестный `/api/nope`
   не уходит в SPA.
2. **Подмена API-ошибок.** Если фильтровать только по префиксу `api/`, путь
   вида `apifoo` может уехать в SPA — префикс проверяем с `/`.
3. **Тест зависит от сборки.** Без `viewer/dist` тест скипается (как
   `test_web_build`), поэтому в CI порядок джоб важен; локально собираем перед
   проверкой.
4. **Относительные ассеты.** `index.html` отдаётся на вложенный путь; Vite
   использует абсолютные `/assets/...` — проверяем, что после fallback ассеты
   грузятся (e2e это ловит).
5. **404 в оболочке.** Если `NotFound` рендерится вне `AppShell` (другая ветка
   роутера), сайдбар исчезнет — маршрут добавляем внутрь `children`, как все
   экраны.
