
# Atlas — IA и дизайн

Документ описывает **размещение компонентов и UX**. Не описывает данные и API
(они не меняются). DESIGN.md не является источником истины — стек здесь
фактический.

## Цель

Переработать веб-интерфейс Atlas в админ-PWA: единый каркас для широкого и
мобильного экрана, онбординг с опросом, экраны сфер, проектов, людей,
файлов, календаря и развития, Apple-подобный календарь, три представления задач
(дерево, доска, гант), тёмная и светлая тема с настраиваемым акцентом и фоном,
LiquidGlass. Поведение API и данные не меняются, кроме миграций из §11.

## Контекст

Viewer — React 19 + Vite + TypeScript, FSD и Steiger, 14 рукописных экранов на
12 табах без роутера, ноль UI-зависимостей, ~800 строк CSS с токенами. Бэкенд —
FastAPI, `features/*`. Разрывы дизайна с API перечислены в §11. Библиотеки:
antd 6, SVAR (канбан, гант), FullCalendar, Recharts, Lucide; AG Grid — вне фазы 1.

## Требования

Функциональные и UX-требования — §2 (маршруты), §3 (онбординг и опрос), §4–§5
(каркасы), §6 (экраны), §7 (тема, акцент, фон, стекло, состояния), §8 (слои и
библиотеки), §11 (бэкенд-разрывы), §12 (порядок работ).

## Acceptance

A1. Широкий экран: липкая шапка (логотип, поиск с `⌘K`, аватар с бейджем),
   левое меню из девяти пунктов, сворачивание. Мобильный: верхняя панель только
   с поиском, четыре нижних таба (Home, Chat, Space, Profile), safe-area.
A2. Онбординг: вход, приветствие, модель с проверкой подключения, Яндекс.Диск
   (можно пропустить), опрос из 9 шагов с превью и утверждением после каждого;
   шаг возобновляется после перезагрузки; «Пропустить опрос» оставляет баннер
   на Главной.
A3. Тема: светлая, тёмная, системная; акцент выбирается пикером по всей палитре;
   текст на акценте проходит контраст; фон — пресет или загруженная картинка с
   затемнением; выбор переживает перезагрузку (localStorage + `UserProfile.data`).
A4. LiquidGlass включён на десктопе и мобильном; без `backdrop-filter` — плотный
   fallback; есть выключатель «меньше эффектов»; на теле таблиц и списков стекла
   нет.
A5. Главная: виджеты «Сегодня», «Ближайшие события», «Входящие» (задачи без
   сферы и проекта), «Развитие», «Файлы», «Агент», KPI; быстрые действия;
   баннеры незавершённой настройки.
A6. Проект: три представления задач — дерево (группировки, поиск, фильтры),
   доска (drag между колонками), гант (зависимости, прогресс, зум); вид хранится
   в URL.
A7. Календарь: Год, Месяц, Неделя, День, Agenda; листание страницами по своей
   гранулярности; сайдбар с календарями сфер; создание протяжкой, перенос и
   resize событий; повторяющиеся — с выбором области «это / будущие / все».
A8. Сферы, Проекты, Люди, Файлы: списки и карточки с поиском, фильтрами и
   деревом; каждая сущность открывается по deep link; хлебные крошки.
A9. Глобальный поиск из шапки ищет по всем сущностям, `⌘K`, страница `/search`
   для «показать все».
A10. У пользователя и у людей — фото: загрузка, кроп, фолбэк инициалами; в
   мобильном и широком каркасе аватар везде один и тот же компонент.
A11. Проверки профиля зелёные: `web-build`, `typecheck-web`, `lint-web`,
   `arch-web`, `unit-tests`, `lint-python`, `typecheck-python`, `arch-python`,
   `schema-check`; плюс Playwright E2E и axe на критические пути.
A12. Старые табы и экраны удалены, с прежних адресов работают редиректы,
   мёртвого кода не остаётся.

## Ограничения

- Только бесплатные и MIT-библиотеки. Enterprise и PRO не покупаем: AG Grid
  Enterprise, SVAR PRO, Bryntum, Syncfusion, Kendo — вне проекта.
- Таблица на миллион строк не входит в фазу 1 (в навигации нет экрана-хозяина),
  AG Grid ставится вместе с ним.
- UI только на русском, i18n не вводим.
- Данные и API не меняются, кроме миграций и эндпоинтов из §11.
- Ноль подавлений: без `eslint-disable`, `type: ignore`, `noqa`; проверки не
  ослабляются.
- Работа в ветке `devkit/<task-id>`, минимальный diff, без абстракций «на
  будущее».
- Таргеты ≥ 44px, видимый фокус, контраст текста ≥ 4.5:1, `prefers-reduced-motion`.

## 1. Принципы

1. **Один хребет навигации.** Широкий экран — левое меню; мобильный — нижние
   табы. Одни и те же маршруты, deep links, работающая кнопка «назад».
2. **Данные на первом плане.** Хром лёгкий: стекло только на шапке, меню,
   модалках, дроверах и карточках дашбордов. Никогда на теле таблицы и длинных
   списков.
3. **Список → деталь.** Любой список имеет поиск, фильтры и группировку; любая
   деталь открывается по URL и имеет хлебные крошки.
4. **Четыре состояния всегда.** Загрузка (скелетон), пусто (CTA), ошибка
   (повтор), успех. Действия — оптимистично + тост.
5. **Клавиатура на десктопе, палец на мобильном.** 44px таргеты, `⌘K`/`Ctrl+K`
   поиск, `Esc` закрывает, фокус-кольцо из акцента.

## 3. Онбординг: 4 шага + опрос из 9 шагов

Сквозное: степпер сверху, «Назад» доступен, состояние шага хранится на сервере
(`OnboardingSession`) — после перезагрузки возвращаемся на тот же шаг. Мобильный —
одна колонка, кнопка действия прижата к низу.

1. **Вход.** Пароль (TOTP нет в API). Ошибка — под полем.
2. **Приветствие.** Название, одна фраза «зачем», три буллета (знания, задачи,
   агенты), кнопка «Начать настройку».
3. **Модель.** Список провайдеров; API-ключ (password, показать/скрыть); модель
   для чата и для анализа; «Проверить подключение» → статус ok/ошибка с текстом.
   Без успешной проверки «Далее» недоступно.
4. **Яндекс.Диск.** Кнопка OAuth, индикатор подключения, «Пропустить».
   Подключение можно завершить позже из настроек.

### 3.1 Опрос — 9 шагов, превью и утверждение после каждого

После каждого ответа — карточка «Создадим: …» со списком и чекбоксами по
пунктам. «Утвердить» создаёт записи сразу; «Пропустить шаг» не создаёт ничего.
Повторный проход шага не дублирует: id созданного лежат в
`OnboardingSession.state`. Всё созданное редактируется позже, «Пропустить опрос»
оставляет баннер на Главной.

| # | Вопрос | Предлагаем | Куда пишется |
|---|---|---|---|
| 1 | О тебе: имя, возраст, город, профессия | карточка профиля | `User.display_name`, `UserProfile.data.context`; каждое поле можно не заполнять и выключить «передавать агенту» |
| 2 | Часовой пояс и рабочие часы | автодетект + подтверждение, дни и часы | `UserProfile.data` + `GrowthSettings.daily_at/weekly_at` |
| 3 | Сферы (2–6) | здоровье, работа, финансы, отношения, развитие, интересы, дом, отдых, смысл + свои; цвет каждой | `Sphere(name, color)` |
| 4 | Цели на квартал (0–3) | текст + сфера + измеримый результат | `Goal(title, sphere_id, target, due_at=+90д)`; `project_id` NULL |
| 5 | Привычки (0–3) | сон 7–8 ч, вода 2 л, 8k шагов, тренировка 3×/нед, чтение 20 мин, без соцсетей до обеда + свои | `Habit(title, cadence, target_per_period)` |
| 6 | Что готов вносить числом ежедневно (0–3) | вес, сон, шаги, пульс покоя, расходы/день, часы фокуса + свои, единица | `Metric(name, kind, unit, cadence)` |
| 7 | Ритм и обзоры | утро/день/вечер для напоминаний; обзор день/неделя/две недели/месяц | `GrowthSettings` |
| 8 | Тон агента | кратко / подробно / по шагам; скорость или глубина | `UserProfile.summary`, `Agent.temperature/instructions` |
| 9 | Приватность | классы материалов: не отдавать агенту и не индексировать (медицина, финансы, личное) | пожелание в профиле; применение к триажу — доработка бэкенда |

После финиша → `/` + тост «Atlas готов».

```
┌───────────────────────────────────────────────────────────────────────┐
│ [logo] Atlas                 [ search ……………… ⌘K ]      [🔔3] [avatar] │ 56px, стекло
├────────────┬──────────────────────────────────────────────────────────┤
│ Главная    │  PageHeader: заголовок · фильтры · действия              │
│ Развитие   │                                                          │
│ Чат        │  контент страницы                                        │
│ Календарь  │                                                          │
│ Сферы      │                                                          │
```

- Шапка липкая. Слева логотип + название. Справа: глобальный поиск (input,

  запоминается.
- Контент: padding 24, максимум не ограничиваем (таблицы), для читаемых
  страниц — 1200.
- Меню профиля (dropdown): Профиль, Настройки, Тема (Светлая/Тёмная/Системная —
  сегмент-контрол), Уведомления, Задания.

## 5. Каркас: мобильный экран

```
┌──────────────────────────────┐
│ [ search …………………………… ]     │ 56px, стекло
│                              │
│  контент страницы            │
│                              │
│                              │
├──────────────────────────────┤
│  Home   Chat   Space  Profile│ 56px + safe-area
└──────────────────────────────┘
```

- Верхняя панель — только поиск. Тап → полноэкранный оверлей: недавние запросы,
  результаты по группам (задачи, документы, люди, файлы, чаты).
- Нижние табы: Home, Chat, Space, Profile. Иконка + подпись, активный — акцент.
  Бейдж непрочитанных — и на Profile. Развитие в табы не добавляем: вход через
  блок на Главной.
- Экраны адаптируются: таблицы → карточки, дерево → drill-down (список групп →
  список → деталь), доска → горизонтальные колонки со снапом, Гант →
  горизонтальный скролл с липкой колонкой задач, календарь → месяц + список дня.
- Действия и фильтры — bottom sheet. Свайп по элементу — основное действие
  (выполнить задачу, прочитать уведомление).

## 6. Экраны

### 6.1 Главная `/`
- Приветствие + дата + часовой пояс.
- Сетка виджетов (широкий 2–3 колонки, мобильный 1): «Сегодня» (задачи с
  чекбоксом), «Ближайшие события» (3), «Входящие» (задачи без сферы и проекта →
  `/tasks?filter=unassigned`), «Развитие» (2–3 привычки, ближайшая цель, метрика
  дня → `/growth`), «Файлы» (последние), «Агент» (последние прогоны и
  предложения), KPI.
- Быстрые действия: задача, файл, событие (на мобильном — FAB).
- Баннеры незавершённой настройки: нет модели / нет диска / опрос не пройден.
- Виджеты — реестр: `{type: 'kpi'|'list'|'chart'|'tasks', props}`. Агент может
  вернуть такой JSON и получить дашборд без правок фронта.

### 6.2 Чат `/chat`, `/chat/:id`
- Широкий: слева список чатов (280px) с поиском и «Новый чат»; справа тред.
  Заголовок треда: название, модель, справа шестерёнка → `/settings/agents`.
- Тред: сообщения, чипы источников (клик → панель документа), индикатор
  инструментов, «Стоп», переключатель «Глубокий анализ», composer с вложением.
- Мобильный: список → тред (назад), composer липкий снизу с safe-area; шестерёнка
  в шапке списка чатов.
- Пусто: подсказки-примеры запросов.

### 6.3 Календарь `/calendar` — Apple Calendar целиком
- **Виды:** Год, Месяц, Неделя, День, Agenda (список). Сегмент-контрол в шапке;
  вид и дата в URL: `/calendar?view=year|month|week|day&date=2026-11-27`.
- **Листание страницами:** prev/next и свайп листают по одному периоду своей
  гранулярности (год → год, месяц → месяц, неделя → неделя, день → день).
  «Сегодня» возвращает к текущей дате.
- **Сайдбар (широкий):** мини-месяц с навигацией; список календарей — сферы и
  проекты, у каждого цвет и чекбокс скрыть/показать; «только этот»; поиск по
  событиям.
- **Год:** 12 мини-месяцев, точки/штрихи событий, клик по месяцу → Месяц,
  клик по дню → День.
- **Месяц:** 6 недель, номера недель, полосы многодневных событий через дни,
  «+N ещё» с раскрытием, выделение сегодня и выходных.
- **Неделя:** сетка 00:00–24:00, линия «сейчас», all-day-строка, многодневные
  полосы, колонки дней с датой и номером недели.
- **День:** та же сетка на один день + список событий справа (широкий) или
  снизу (мобильный).
- **Событие — поповер с полным набором:** название, время, календарь (сфера,
  проект), место, заметка, участники (люди Atlas), повтор (RRULE), напоминания,
  ссылки; «Изменить», «Удалить», «Открыть задачу/проект».
- **Взаимодействие:** клик по дню (Месяц/Год) или протяжка по времени (Неделя/
  День) — быстрое создание; drag события — перенос, resize — длительность;
  изменение повторяющегося события спрашивает область «это / это и будущие /
  все».
- **Цвет:** календарь = сфера (цвет сферы), проект наследует цвет сферы;
  прошедшие события приглушены.
- **Мобильный:** Год — сетка 3×4 мини-месяцев; Месяц — грид + список дня под ним;
  Неделя — горизонтальная лента дней + вертикальный список; День — тайм-слоты;
  свайп по датам; FAB «+».
- **Реализация:** FullCalendar 6.1.22 (MIT) — Месяц/Неделя/День (drag, resize,
  select, all-day, многодневные полосы бесплатны) + `@fullcalendar/multimonth`
  для Года; сайдбар, поповер, скин и Apple-поведение — свои. Если Год не сойдётся
  по виду, свой год-грид (~150 строк: 12 мини-месяцев), остальные виды остаются
  на FullCalendar.

### 6.4 Сферы `/spheres`
- Сетка карточек (3/2/1): название, цвет/иконка, счётчики (проекты, задачи,
  люди, файлы), прогресс, последняя активность.
- Сводка сверху: всего сфер/проектов/задач. Кнопка «Сфера».
- Фильтр активные/архив. Пусто — CTA создать первый сфера.

### 6.5 Сфера `/spheres/:id`
- Шапка: название, цвет, редактировать.
- Дашборд виджетов сферы (метрики, активность, ближайшие события).
- Проекты сферы (список).
- Задачи без проектов этого сферы (дерево, группировка по статусу).
- Люди сферы, файлы сферы.
- CTA «Новый проект».

### 6.6 Проекты `/projects`
- Тулбар: поиск, фильтр по сферау/статусу, сортировка. Переключатель вид
  «список / карточки».
- Список — antd Table: название, сфера, прогресс, задачи (сделано/всего), даты,
  статус. Строка → проект.

### 6.7 Проект `/projects/:id`
- Шапка: название, сфера, статус, прогресс-кольцо, даты, действия.
- Дашборд проекта + таймлайн (вехи/Гант-сводка).
- Задачи — переключатель представлений (сегмент-контрол, вид в URL):
  - **Список (дерево)**: группировки по статусу/исполнителю/тегу, поиск,
    фильтры, сворачивание, клик → деталь задачи.
  - **Доска**: SVAR Kanban, колонки по статусу, drag между колонками, своя
    карточка. Swimlanes — PRO, без них.
  - **Гант**: SVAR Gantt, зависимости, прогресс, drag/resize, зум
    день/неделя/месяц.

### 6.8 Задачи `/tasks`
- Дефолтный фильтр «Без сферы и проекта» виден чипом; рядом «Все задачи».
- Дерево с группировкой по статусу/сроку, поиск, фильтры (сфера, проект,
  исполнитель, срок). Быстрое добавление в шапке.
- Мобильный: список, свайп — выполнить, bottom sheet фильтров.

### 6.9 Люди `/people`
- Сетка карточек: фото (или инициалы), имя, роли, чипы сфер, последний контакт,
  открытые задачи. Поиск. Пусто — CTA.

### 6.10 Человек `/people/:id`
- Профиль: фото (или инициалы), имя, роли, контакты, заметки.
- Связи: сферы, проекты. Задачи. Файлы. Хронология взаимодействий.

### 6.11 Файлы `/files`
- Дерево: сфера → проект → файлы; поиск; сортировка по имени/дате загрузки;
  хлебные крошки. Строка: тип, имя, размер, дата, статус обработки (бейджи
  загрузки/OCR/ошибки), действия (открыть, скачать, переиндексировать, удалить).
- Мобильный: drill-down по группам.

### 6.12 Файл `/files/:id`
- Просмотр (PDF/картинка/текст), метаданные, сфера/проект, статус обработки и
  задание, действия (скачать, переиндексировать, удалить, связать).

### 6.13 Профиль `/profile`
- Фото (загрузка, кроп, инициалы как фолбэк), имя, возраст, город, профессия
  (контекст для агента, тумблер «передавать агенту»), часовой пояс, пароль,
  настройки внешнего вида.
- Ссылки: Настройки, Уведомления, Задания, Выход.

### 6.14 Настройки `/settings`
Разделы: Профиль · Внешний вид (тема, акцент пикером, «эффекты» вкл/выкл,
плотность) · Агенты · Интеграции (модель, Яндекс.Диск) · Уведомления · Данные
(экспорт, бэкапы).

### 6.15 Агенты `/settings/agents`
- Список агентов (сфера, роль, модель, инструменты, вкл/выкл), создание,
  редактирование промпта, последние запуски.
- Открывается из чата (шестерёнка) и из настроек.

### 6.16 Уведомления `/notifications`
- Список с непрочитанными, отметка «прочитать», фильтр по типу, переход к
  сущности. Настройки push.

### 6.17 Задания `/jobs`
- Список заданий: тип, статус, прогресс, время, логи, повтор.

### 6.18 Поиск `/search`
- Результаты по группам: задачи, проекты, сферы, люди, файлы, документы, чаты.
  Счётчик на группу, «показать все», подсветка совпадений.

### 6.19 Развитие `/growth`
- Шапка: период (неделя / месяц / квартал), «Сформировать обзор».
- Табы: Цели · Привычки · Метрики · Дневник · Обзоры (на мобильном — горизонтальный
  скролл табов).
- Виджеты: цели (прогресс, срок, история), привычки (стрики, отметки на сегодня),
  метрики (линия + сравнение с прошлым периодом), дневник (последние записи),
  обзоры (лента).
- Быстрые действия: отметить привычку, записать метрику, запись в дневник.
- На Главной — блок-сводка «Развитие» (2–3 привычки, ближайшая цель, метрика дня)
  с переходом на страницу; на мобильном это единственный вход.
- На широком экране — отдельный пункт меню «Развитие».

## 7. Сквозные правила

- **Тема, акцент, шрифт, фон.** Один файл токенов: `--bg/--surface/--surface-glass/
  --text/--muted/--border/--accent/--accent-contrast/--ok/--warn/--danger/
  --glass-*/--bg-image/--bg-scrim/--radius/--font`. Акцент — antd `ColorPicker` по
  всей палитре → `colorPrimary`; производные `color-mix(in oklab, …)`; контраст
  текста на акценте считается по яркости (на жёлтом белый текст не ставим).
  Шрифт — системный стек без веб-шрифтов, в таблицах `tabular-nums`. Фон страницы
  — пресет (градиент) или своя картинка: загрузка, `object-fit`, позиция, размытие
  и обязательный скрим `--bg-scrim` под контраст текста; на мобильном фон
  фиксированный, чтобы не дёргался при скролле.
- **LiquidGlass.** Стекло на шапке, меню, модалках, дроверах, карточках
  дашбордов — и на десктопе, и на мобильном. На мобильном радиус размытия ниже
  (12–14px вместо 18–20px) ради FPS. Fallback без `backdrop-filter`,
  `prefers-contrast`, настройка «меньше эффектов», скрим под текстом
  (контраст ≥ 4.5:1). На теле таблиц и списков — непрозрачные поверхности.
- **Поиск.** Один компонент на десктоп и мобильный; запросы по всем сущностям;
  `⌘K`.
- **Состояния.** Скелетон вместо «Загрузка…», пусто с CTA, ошибка с «Повторить»,
  тосты через antd `message`.
- **Доступность.** Фокус виден всегда, акцент не единственный носитель смысла,
  таргеты ≥ 44px, `prefers-reduced-motion` — без анимаций.

## 9. Технические ограничения, которые влияют на дизайн

- AG Grid Community: grouping/tree data/master-detail — Enterprise. Поэтому
  деревья свои, а AG Grid — только для действительно больших плоских таблиц.
- SVAR Kanban: swimlanes, undo/redo, экспорт, динамическая подгрузка — PRO.
  Бесплатно: drag, редактор карточки, фильтры/сортировки/группировки, свои
  шаблоны, stack-layout для мобильного.
- SVAR Gantt: критический путь, базовые линии, ресурсные ряды не заявлены в
  free — если нужны, доработка.
- FullCalendar 7 в переходном состоянии (плагины ещё 6.1.22) — пиновать 6.1.22.
  Год-вид берём из `@fullcalendar/multimonth` (MIT); если вид не сойдётся с
  Apple — свой год-грид поверх тех же данных.
- Четыре CSS-системы (antd, AG Grid, SVAR, FullCalendar) → один файл токенов,
  темы всех четырёх водятся из него. Скин — часть задачи, а не «потом».

## 10. Принятые допущения (поправь, если не так)

1. Календарь — **полный Apple Calendar**: Год, Месяц, Неделя, День, Agenda;
   листание страницами по своей гранулярности; создание/перенос/resize событий,
   повторы, напоминания. Общий паттерн Apple (сайдбар со списками + основная
   область + поповеры вместо модалок) применяем и к спискам сущностей.
2. «Развитие» — отдельный пункт меню на широком экране + блок на Главной;
   на мобильном только через Главную (нижние табы не меняются).
3. Опрос на онбординге можно пропустить (баннер на Главной), чтобы не
   блокировать вход.
4. Уведомления и Задания живут в меню профиля, отдельными страницами.
5. Глобальный поиск ищет по всем сущностям и открывается `⌘K`; отдельная
   страница `/search` нужна для «показать все» из оверлея.
6. «Входящие» — это задачи без сферы и проекта; сущность заметок не вводим.
7. Стекло включено и на десктопе, и на мобильном; фон страницы — пресет или
   картинка пользователя с затемнением под контраст.
8. У пользователя и у людей — фото с загрузкой; фолбэк — инициалы.
9. Опрос — 9 шагов с превью и утверждением после каждого; пресеты сфер:
   здоровье, работа, финансы, отношения, развитие, интересы, дом, отдых, смысл.
10. Термин: в UI «сфера» → **«Сферы»** (пункт меню, страницы `/spheres`).
    «Развитие» занято страницей роста (цели, привычки, метрики). В коде и API
    сущность остаётся `Sphere` / `/api/spheres` — переименование только в UI.

## 11. Разрывы с бэкендом и открытые решения

Проверено по `app/backend/features/*`. Дизайн местами опережает API — это
надо закрыть до постановки задачи или сознательно урезать фазу 1.

| Дизайну нужно | Что есть | Решение |
|---|---|---|
| Цвет и иконка сферы (весь календарь и карточки — на цвете) | `Sphere`: только `name` | миграция сферы, обязательна (в коде сущность остаётся `Sphere`) |
| Старт/прогресс задачи, старт/вехи проекта (Гант, таймлайн) | `Task.due_at`, `Project.due_at` | миграция задач и проектов в бэкенд-задаче эпика |
| Зависимости задач для Ганта | `TaskDependency(blocked_by)` есть | ок, тип связи только «блокирует» |
| Дерево задач | `Task.parent_id` есть | ок |
| Глобальный поиск по всем сущностям | `/api/search` — только документы | новый эндпоинт `scope=all` |
| Агрегаты сферы/проекта (прогресс, счётчики, активность) | нет | серверные `summary`-эндпоинты |
| Дашборды, генерируемые агентом | нет ни контракта, ни хранения, ни инструмента | контракт + реестр виджетов в фазе 1; агент — фаза 2 |
| Виджет «Входящие» на Главной | задачи без `sphere_id`/`project_id` есть | ок: «Входящие» = задачи без сферы и проекта, заметок не вводим |
| Часовой пояс пользователя | `ATLAS_TIMEZONE` — глобальный env, у `User` поля нет | per-user TZ (колонка или `UserProfile.data`), использовать в напоминаниях, «Сегодня» и календаре |
| Фото пользователя и людей | `User`: username+hash; `Person`: без фото | миграция `User.display_name/avatar_ref`, `Person.photo_ref`; upload + ресайз (Pillow уже в зависимостях) |
| Возраст/город/профессия для контекста агента | `UserProfile.data: JSON` | ок, без миграции; тумблер «не передавать агенту» |
| Состояние шагов опроса и защита от дублей | `OnboardingSession.state: JSON` | ок, хранить созданные id |
| Фон страницы, тема, акцент | `UserProfile.data: JSON` (миграция не нужна) | файл фона — в storage владельца, ссылка в `UserProfile.data`; пресеты — CSS-градиенты |
| TOTP в онбординге | `/api/auth/*`: только login/logout/me | убрать TOTP из шага 1 |
| Состояние шагов онбординга (модель/диск/опрос) | `OnboardingSession` только для опроса | шаги 3–4 вычислять по наличию LLM-ключа и интеграции Yandex |
| «Файлы» в навигации | сущность одна — `Document` | «Файлы» = документы, без новой сущности |
| Таблица на 1M строк | в навигации экрана-хозяина нет | **решено: не в фазе 1**; AG Grid ставим, когда появится экран-хозяин (чанки знаний / метрики / «Данные») |

**Решения по умолчанию (если не поправят):**

- Роутер — React Router 8.5.3 (проверено в npm 2026-11-27); данные — TanStack Query, `useResource` уходит.
- Иконки — Lucide (ближе к Apple, чем antd icons); логотип — текстовый вордморк
  до появления ассета.
- Тема, акцент и фон — localStorage для первого кадра + `UserProfile.data`.
- «Эффекты» (стекло) — включены на десктопе и на мобильном; в настройках есть
  выключатель «меньше эффектов» для слабых устройств.
- Аватары — фото с загрузкой и кропом, фолбэк — инициалы на цвете сферы/акцента.
- Офлайн кэш новых экранов — только Главная и Чат, остальное онлайн.
- E2E — Playwright + axe в профиль проверок (логин, онбординг, задача/проект,
  календарь-создание, файлы); без этого глубокую переработку нечем принимать.
- Календарь-Год — дневной спайк: `multimonth` FullCalendar против своего грида,
  решение по факту.

## 12. Порядок работ (эпик)

Режим — **AgentTeam**: задачи с непересекающимся scope и брифами, независимая
проверка не-автором. Параллельно после задач 1–2 идут 4, 6, 7, 8; задачи 3 и 5
после бэкенда и экранов.

| # | Задача | Размер | Зависит от |
|---|---|---|---|
| 1 | Shell: роутер, шапка/меню/нижние табы, токены, тема, акцент, фон, стекло | L | — |
| 2 | Бэкенд: миграции (цвет/иконка сферы, старт/прогресс задач, старт проекта, `display_name`/avatar, фото человека, per-user TZ) + эндпоинты (avatar/фон upload и ресайз, `summary` сферы/проекта, `search?scope=all`) | L | — |
| 3 | Онбординг: 4 шага + опрос 9 шагов с превью | L | 1, 2 |
| 4 | Главная, Развитие, Профиль, Сферы (список/карточка), Проекты, Люди (список/карточка) | XL | 1, 2 |
| 5 | Проект: дерево / доска / гант | XL | 2, 4 |
| 6 | Календарь Apple целиком (+ спайк года) | XL | 1, 2 |
| 7 | Файлы/Файл, Настройки, уведомления, задания, поиск | L | 1, 2 |
| 8 | Чат + настройки агентов | M | 1 |
| 9 | Качество: Playwright + axe, проверки, удаление старых страниц | M | все |

Порядок: 1 → 2 → 3 → 4 → 5/6/7/8 → 9. Задачи 3, 4, 5, 6 — XL: внутри отдельный
коммит и приёмка на каждый экран, чтобы ревью не превращалось в один диф на
весь фронтенд. AG Grid в фазу 1 не входит.
