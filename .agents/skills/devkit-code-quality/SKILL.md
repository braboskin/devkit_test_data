# devkit-code-quality — качество кода

## Когда

Нужно включить или расширить контроль качества (линт, типы, формат, хуки, CI);
новый проект без проверок; legacy-код «грязный», и агент пишет «как попало»;
перед серией задач надо зафиксировать планку, чтобы правки не ухудшали код.
Не для разовой правки стиля — это `devkit-just-do`.

## Инструменты

- `devkit profile show|set|test` — стек проекта и его команды проверок;
- `devkit task check`, `devkit doc show` — фиксация результатов и контекст;
- git (`status`, `diff`, `log`), grep/read; конфиги проекта (package.json,
  pyproject.toml, Makefile, CI) — только чтение;
- graphify (опционально) — карта зависимостей; ponytail (опционально) —
  правила минимального решения;
- Полный CLI-набор devkit: `devkit task plan`, `devkit task check`, `devkit task report`, `devkit doc`, `devkit profile`; применяй только относящиеся к навыку.

## Шаги

1. Возьми стек из профиля, а не из памяти: `devkit profile show --json` и
   прочитай `app.stack` из профиля (в JSON путь
   `profile.profile.app.stack`). Если профиль `missing`/`invalid` — сначала
   `devkit-profile-setup`, здесь только план проверок.
2. По одному инструменту на роль и на язык: линтер, проверка типов, форматтер.
   Дубли (два линтера на один язык) не добавляй; уже подключённое не заменяй
   без причины.
3. **Clean Slate.** Включай проверку на всём проекте, а существующие нарушения
   гаси подавлениями (disable-комментарий, exclusion-список) — не переписывай
   legacy ради прохождения. Каждое подавление — исключение с причиной и
   владельцем в конфиге. Критерий долга: «ноль непомеченных подавлений,
   каждое с причиной».
4. Формат — только для staged и новых файлов (`lint-staged` или аналог).
   Массовый reformat всего репозитория — отдельным коммитом и с
   `.git-blame-ignore-revs`, иначе `git blame` теряет историю.
5. Хуки — один диспетчер на репозиторий. Проект с `core.hooksPath` глушит
   второй менеджер: не ставь два (`husky` + `pre-commit`) в один репозиторий.
6. Каждая проверка оформляется командой профиля (`verification`), чтобы
   `devkit-task-verify` запускал её одной командой. Обязательность
   (`required: true`) решает владелец, не агент.
7. Долг выплачивай отдельными коммитами до нуля по счётчику подавлений; сам
   факт «проверка включена» не доказательство — нужен прогон.

## Промпты субагентов

- `.agents/prompts/test-engineer.md` — проверить полноту проверок: каждая
  категория (линт/типы/формат/тесты) реально ловит нарушение, а не даёт 0 на
  текущей раскладке; вернуть команды и exit code.
- `.agents/prompts/skeptic.md` — аудит «проверка без зубов»: подавления без
  причины, конфиги, отключённые правила, фиктивные команды.
- Промпт роли подставляется в `prompt` вместе со списком файлов/команд;
  историю чата не передавай. Автор изменений не выносит финальный вердикт.

## Если инструмент недоступен

- graphify нет → `grep`/`rg` + чтение конфигов и `git log` по истории команд.
- ponytail нет → правила `devkit-lifecycle`: минимальный работающий diff,
  stdlib/native вместо зависимостей, одна проверка на нетривиальную логику.
- `devkit profile test` не работает → прогоняй команды профиля вручную, пиши
  в отчёт команду, вывод и exit code; не помечай проверку пройденной.
- Нет сети для установки линтера → не выдумывай конфиг; зафиксируй, что
  проверка не настроена, и эскалируй доступ.
- Нет CI-конфига и доступа к нему — проверяй локальными командами профиля и
  отметь, что CI-проверка не проверена.

## Доказательства

- `devkit profile show --json`: какие проверки существуют, какие `required`.
- Команда, вывод, exit code и commit sha для каждой новой проверки.
- Список подавлений: файл/правило, причина, владелец.
- Отчёт `docs/reports/<id>.md`: что включено, что осталось в долге, что не
  проверено (CI, хуки, платформы).

## Если не получилось

Инструмент не ставится, проверка не воспроизводится или конфликтует с
существующей — не отключай её молча и не расширяй scope: зафиксируй проблему и
вызови `devkit-team-escalate` с конкретным запросом (доступ, сеть, решение
владельца об исключении). Красную проверку не помечай зелёной.
