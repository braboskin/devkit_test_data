# devkit-team-escalate — остановка и эскалация

## Когда

Блокер, который нельзя решить в рамках задачи: неоднозначные требования,
нет доступа/секрета, конфликт ролей, две неудачные попытки подряд, риск для
данных или безопасности, ожидание решения владельца. Не используй вместо обычной
итерации исправлений.

## Инструменты

- `devkit task status <id> blocked --reason "<кратко>"`, `devkit task comment`
- `devkit task show|report`
- git (`status`, `commit`, `log`), grep/read, graphify (опционально), ponytail
- Полный CLI-набор devkit: `devkit task plan`, `devkit task check`, `devkit task report`, `devkit doc`, `devkit profile`; применяй только относящиеся к навыку.

## Шаги

1. Останови все пишущие процессы/субагентов. Не давай им продолжать фоном.
2. Сохрани работу, не теряя данные: закоммить WIP в ветку `devkit/<id>` с
   пометкой `wip:` (если коммит допустим правилами `devkit-git`) или явно
   перечисли незакоммиченные файлы. Не удаляй и не откатывай чужие правки.
3. Сформулируй блокер фактами:
   - что делал и где остановился (шаг плана, файлы);
   - последняя ошибка/вывод с id проверки или exit code;
   - что уже пробовал (не больше двух попыток) и почему не сработало;
   - что именно нужно от владельца: решение, доступ, секрет, уточнение
     acceptance, изменение scope.
4. Переведи задачу: `devkit task status <id> blocked --reason "<...>"` и
   добавь комментарий с полным описанием. Отметь в отчёте раздел «Блокер» и
   приложи ссылки на артефакты.
5. Уведоми владельца через web (событие/комментарий появится в задаче). Не
   подменяй это сообщением в чат, если задача живёт в web.
6. Ожидай решения. Возобновление: только после ответа владельца; при новом
   направлении — `devkit-replan`, статус `in_progress`; при отмене — `cancelled`.

## Промпты субагентов

Служебный навык; субагентов не запускает. Если для диагноза нужен второй
взгляд — разрешён один субагент с `.agents/prompts/skeptic.md` или
`.agents/prompts/architect.md`, с брифом «только диагноз, без правок и без
вердикта». Историю чата не передавай.

## Если инструмент недоступен

- `devkit task status`/`comment` не подключены → запиши блокер в
  `docs/reports/<id>.md` и `tasks/<id>.md`, отметь деградацию, не выдумывай
  обходной API.
- graphify нет → приложи `git status`, `git diff`, grep/read, логи команд.
- ponytail нет → правила `devkit-lifecycle` (остановиться дешевле, чем
  чинить наугад).
- Нет доступа к web → передай владельцу факты и текущий статус; не продолжай
  реализацию.

## Доказательства

- Статус `blocked` и причина; комментарий/отчёт с фактами.
- WIP-коммит или список незакоммиченных файлов; `git status`.
- Вывод последней ошибки, id упавших проверок, находки, что пробовал.
- Явный запрос к владельцу с вариантами решения.

## Если не получилось

Если эскалация не доходит до владельца (нет web/CLI), оставь задачу в
безопасном состоянии: не мержить, не выпускать, не удалять, не «доделывать
молча». Зафиксируй это в отчёте и в финальном ответе координатору. Повторная
попытка решить блокер без новых данных запрещена.
