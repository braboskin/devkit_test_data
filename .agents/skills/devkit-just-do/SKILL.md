# devkit-just-do — мелкая правка без плана

## Когда

Только при одновременном выполнении условий:

- размер S: 1–2 файла, ориентировочно до ~50 строк;
- нет миграций БД, изменений auth/денег/секретов, новых зависимостей и
  публичных API;
- acceptance очевиден из задачи;
- изменения покрываются существующими тестами или одной новой runnable проверкой;
- нет незакрытого эпика, требующего декомпозиции.

Если условие перестало выполняться в процессе — остановись и перейди в
`devkit-task-plan`, не дожимай «как-нибудь».

## Инструменты

- `devkit task show|status|comment|check|report|plan` (план не создаётся)
- `devkit profile show|test`, `devkit doc list|show`
- git (`status`, `diff`, `log`), grep/read, graphify (опционально), ponytail
- Полный CLI-набор devkit: 	ask plan, 	ask check, 	ask gate, 	ask report,
  doc, profile; применяй только относящиеся к навыку.

## Шаги

1. Прочитай `tasks/<id>.md`, acceptance и затронутый код. Найди всех вызывающих
   изменяемую функцию — правка симптома в одном месте не считается.
2. Пройди лестницу ponytail: не нужно ли вообще; нет ли готового helper/util;
   stdlib; нативная возможность; уже установленная зависимость; одна строка.
   Возьми первый работающий вариант, не строй «правильную архитектуру».
3. Сделай минимальный diff в ветке `devkit/<id>` (см. `devkit-git`). Не трогай
   файлы вне scope, не форматируй чужой код, не добавляй зависимости.
4. Добавь ровно одну проверку, которая упадёт при поломке логики (assert-демо
   или маленький тест), если существующие тесты это место не покрывают.
5. Прогони проверку и обязательные проверки профиля:
   выполни команду и запиши `devkit task check <id> --name <check> --status passed|failed --output "<вывод>"`; при отсутствии CLI —
   команда из профиля + запись результата в отчёт.
6. Обнови `docs/reports/<id>.md`, поставь `needs_review` и передай на
   независимую проверку (`devkit-team-check`) или владельцу.

## Промпты субагентов

Обычно не нужны. Если потребовался второй взгляд — используй
`.agents/prompts/skeptic.md` или `.agents/prompts/test-engineer.md`, подставив
в `prompt` субагента бриф и diff; не передавай историю чата.

## Если инструмент недоступен

- graphify нет → `grep`/`rg` + чтение + `git log -S`; отметь деградацию.
- ponytail нет → правила `devkit-lifecycle`: минимальный работающий diff,
  stdlib/native вместо зависимостей, одна runnable проверка.
- `devkit task check` не подключён → выполни команду вручную, сохрани вывод и
  exit code в отчёт; не выдумывай id проверки.
- Нет профиля/проверок → остановись и запусти `devkit-profile-setup`.

## Доказательства

- `git diff --stat` и коммит с id задачи.
- Команда проверки, её вывод (сокращённый), exit code, commit sha.
- Строка в `docs/reports/<id>.md`: что изменено, что проверено, что осталось.

## Если не получилось

Одна повторная попытка с уточнённой гипотезой. Затем — не расширяй задачу и не
пропускай проверку: зафиксируй `blocked` через `devkit-team-escalate`, приложи
вывод ошибки и что именно нужно от владельца. Задачу в `done` не переводи.
