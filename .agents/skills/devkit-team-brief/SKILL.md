# devkit-team-brief — бриф субагенту

## Когда

Перед запуском любого субагента в AgentTeam или при передаче workstream
другому агенту. Бриф заменяет историю чата: ребёнок получает только то, что
нужно для его scope.

## Инструменты

- `devkit task brief <id> --json`,
  `devkit task show|plan|check`
- `devkit profile show|json`, `devkit doc show`
- git (`diff`, `log`), grep/read, graphify (опционально), ponytail
- субагенты DSH: `subagent`
- Полный CLI-набор devkit: 	ask plan, 	ask check, 	ask gate, 	ask report,
  doc, profile; применяй только относящиеся к навыку.

## Шаги

1. Определи workstream: роль, один результат, точные пути/репозитории,
   зависимости от других workstreams.
2. Собери бриф из источников, не из пересказа:
   - **Задача**: id, заголовок, тип, acceptance (дословно);
   - **План**: только релевантные шаги и версия;
   - **Scope**: что можно менять, что запрещено, какие файлы общие;
   - **Проверки**: команды/имена из профиля, ожидаемый результат;
   - **Токен**: имя переменной `DEVKIT_TOKEN`, роль и scopes (сам токен — вне
     брифа, передаётся через окружение/файл 0600);
   - **Роль-промпт**: путь `.agents/prompts/<role>.md` (содержимое подставит
     вызывающий в `prompt`);
   - **Формат ответа**: файлы, коммиты, команды, exit code, что не проверено,
     открытые вопросы;
   - **Запреты**: не выходить за scope, не подтверждать гейты, не менять
     проверки, не трогать секреты, не расширять задачу.
3. Уложи бриф в разумный объём: план целиком нужен редко; вырезай всё, что не
   влияет на решения ребёнка. Не вставляй историю чата, эмоции и прошлые
   обсуждения — только факты и требования.
4. Сохрани бриф (например, `devkit task brief` выводит JSON; либо файл в
   `.devkit/briefs/<role>-<sha>.md`, который не коммитится) и приложи его hash
   в run-запись.
5. Запусти субагента: `prompt` = содержимое `.agents/prompts/<role>.md` + бриф.
   Передай только его workstream; не проси «сделать всю задачу».

## Промпты субагентов

Этот навык готовит вход для промптов из `.agents/prompts/`:
`analyst`, `architect`, `designer`, `techwriter`, `skeptic`,
`backend-engineer`, `frontend-engineer`, `test-engineer`. Выбор роли
определяется workstream; один ребёнок — одна роль. Промпт подставляется в
`prompt`, а бриф — данные к нему.

## Если инструмент недоступен

- `devkit task brief` не подключён → собери бриф вручную из `tasks/`,
  `plans/`, `docs/` и профиля; отметь деградацию.
- graphify нет → не нужен для брифа; используй файлы, grep/read и `git log`.
- ponytail нет → добавь в бриф правило минимального diff из
  `devkit-lifecycle`.
- Нет профиля проверок → включи в бриф «проверки не настроены» и не запускай
  исполнителя до `devkit-profile-setup`.

## Доказательства

- Бриф с версией плана, scope, acceptance и списком проверок.
- Hash/путь брифа в run-записи; связь бриф ↔ ребёнок ↔ workstream.
- Ответ ребёнка в формате контракта, а не «готово».

## Если не получилось

Если workstream нельзя ограничить непересекающимся scope — не запускай двух
писателей в одни файлы. Разбей иначе или поставь последовательность. Если
ребёнку не хватает контекста, дополни бриф фактами из плана/кода, но не
передавай чат. Не решай конфликт scope «по ходу» — эскалируй.
