# devkit-epic-plan — план эпика и декомпозиция

## Когда

Эпик создан, но у него нет плана; крупная фича требует нескольких задач;
нужно упорядочить существующие задачи по зависимостям и scope. Для одной
задачи используй `devkit-task-plan`.

## Инструменты

- `devkit epic show|create|list`, `devkit task create|show|list|plan`
- `devkit doc list|show|put`, `devkit profile show|test`
- `devkit task report|comment`
- git, grep/read, graphify (опционально), ponytail
- Полный CLI-набор devkit: 	ask plan, 	ask check, 	ask gate, 	ask report,
  doc, profile; применяй только относящиеся к навыку.

## Шаги

1. Прочитай эпик `epics/<id>.md`, ТЗ (`docs/`, `tz_path`), ADR, профиль и
   текущее состояние задач эпика. Проверь, что цель и критерии готовности
   сформулированы; недостающие вопросы — владельцу (не больше трёх блокирующих).
2. Исследуй архитектуру: какие репозитории/слои затронуты, что уже есть,
   какие интерфейсы придётся менять. graphify — карта зависимостей; при
   отсутствии — grep/read/git.
3. Построй план эпика `docs/plans/epic-<id>.md`:
   - цель и критерии готовности эпика;
   - этапы (milestones) с результатом каждого;
   - список задач: id/название, тип (`feature`/`bug`/`chore`), размер, scope
     (точные пути), acceptance, проверки, зависимости;
   - порядок выполнения и параллельные ветки;
   - риски, миграции, что не входит в эпик.
4. Декомпозируй так, чтобы задачи были независимы по файлам и могли идти
   параллельно. Пересечение scope — только с явной зависимостью в `depends_on`.
   Одна задача — один проверяемый результат; не дроби на «полдела».
5. Создай задачи через `devkit task create` в порядке зависимостей, привяжи к
   эпику, запиши `scope`, `verification`, `depends_on`. Задачи без профиля
   проверок не создавай — сначала `devkit-profile-setup`.
6. Запроси подтверждение плана у владельца (web). После approval переведи эпик
   в активную работу и передай задачи в `devkit-task-plan` / `devkit-team-run`.

## Промпты субагентов

- `.agents/prompts/analyst.md` — требования, границы эпика, acceptance;
- `.agents/prompts/architect.md` — этапы, зависимости, технический долг;
- `.agents/prompts/designer.md` — UX/UI-этапы и критерии, если есть интерфейс;
- `.agents/prompts/techwriter.md` — структура плана, ТЗ и документации.
Файл роли подставляется в `prompt` субагента вместе с эпиком и ТЗ; без истории
чата. Итоговый план и задачи создаёт основной агент.

## Если инструмент недоступен

- graphify нет → grep/read, `git log`, анализ структуры каталогов.
- ponytail нет → правила `devkit-lifecycle` (не дроби лишнего, минимальные задачи).
- `devkit task create` не подключён → подготовь файлы задач в `tasks/` и план,
  отметь деградацию; владелец создаст записи после восстановления CLI.
- Нет ТЗ → не выдумывай требования: зафиксируй пробел и эскалируй.

## Доказательства

- Файл плана эпика с commit sha и approval владельца.
- Список созданных задач с id, зависимостями, scope и проверками.
- Матрица покрытия: критерий эпика → задачи → проверки.
- Явный список того, что в эпик не входит.

## Если не получилось

Если декомпозиция упирается в неизвестную архитектуру или конфликт требований,
не создавай «задачи-заглушки». Остановись, приложи карту неясностей и вызови
`devkit-team-escalate` (`blocked`) с вариантами: уточнить ТЗ, сделать
исследовательскую задачу, урезать эпик.
