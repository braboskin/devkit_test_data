# План S2d: Онбординг — вход, модель, диск, опрос из 9 шагов

## Контекст

- Сейчас: `App` держит гейты и старый `SetupWizard` (LLM → Яндекс.Диск →
  диалоговый онбординг), страница `pages/onboarding` — старый диалог из M3.
- Бэкенд готов: `/api/auth/login`, `/api/settings/llm` (+check), `/api/settings/yadisk`,
  `/api/onboarding` (start/answer/finish), `OnboardingSession.state`,
  `UserProfile.data` (контекст, UI).
- ТЗ §3/3.1: 4 шага визарда + опрос 9 шагов с превью и утверждением после
  каждого, пропуск, возобновление; Acceptance A2.

## Шаги

1. Маршруты онбординга: `/login`, `/welcome`, `/setup/model`, `/setup/disk`,
   `/survey`. `App` оставляет только проверку сессии, дальше — гейт по
   незавершённому шагу (редирект); шаги «модель» и «диск» считаются
   выполненными по факту наличия LLM-ключа и интеграции (без отдельного
   состояния).
2. `pages/onboarding`: степпер, карточка вопроса, **превью «Создадим: …»** с
   чекбоксами и утверждением после каждого шага, «Пропустить шаг»,
   «Пропустить опрос» (баннер на Главной). Состояние — `OnboardingSession`;
   повторный проход не дублирует (id созданного в `state`).
3. Шаг «О тебе»: имя, возраст, город, профессия → `UserProfile.data.context`,
   тумблер «передавать агенту».
4. Пресеты сфер: здоровье, работа, финансы, отношения, развитие, интересы,
   дом, отдых, смысл (+ свои).
5. `pages/login` и шаги «модель»/«диск» — на обёртках antd (`TextField`,
   `Button`, `SelectField`), проверка подключения модели, OAuth с пропуском.
6. Мобильная раскладка: одна колонка, действие прижато к низу.
7. Проверки и отчёт.

## Acceptance

- Новый пользователь проходит: вход → приветствие → модель (с проверкой) →
  Яндекс.Диск (можно пропустить) → опрос 9 шагов → Главная.
- После перезагрузки на любом шаге возврат на тот же шаг.
- Утверждение после каждого вопроса создаёт записи; повтор не дублирует.
- «Пропустить опрос» оставляет баннер на Главной.
- Контекст профиля сохраняется и передаётся агенту по тумблеру.
- Экраны — на компонентах `shared/ui`, без прямых импортов antd.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web` — с exit
code в отчёт; сценарий онбординга войдёт в e2e в S4.

## Scope

`viewer/src/pages/{onboarding,login}`, `viewer/src/app/{App.tsx,router.tsx,SetupWizard.tsx}`,
`viewer/src/pages/home` (баннер). Бэкенд не меняется.

## Риски

- **Гейт и роутер**: перенос потока из `App` в маршруты может сломать офлайн- и
  SPA-fallback; проверить прямые ссылки и PWA.
- **Идемпотентность**: `OnboardingSession.state` хранит созданные id; после
  сбоя сети повторный шаг не должен плодить сферы/цели.
- **Миграция данных**: старые диалоговые ответы (если есть) не ломают новый
  опрос; при отсутствии `answers` — старт с первого шага.
- **PII**: контекст (возраст/город/профессия) хранится в профиле и передаётся
  агенту только при включённом тумблере.
