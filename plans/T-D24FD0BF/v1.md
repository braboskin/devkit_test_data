# План T-D24FD0BF — подключение LLM: провайдер, ключ, список моделей

## Контекст

- Бэкенд: `features/settings/routers/settings_llm.py` — `GET/PUT/DELETE
  /api/settings/llm`, `POST /api/settings/llm/check`; `ApiKey` = строка 8..4096
  без пробелов; `PUT` требует `api_key` всегда. `features/settings/service.py`:
  `set_llm` шифрует через `core/crypto`, `check_llm` расшифровывает ключ и зовёт
  `agent.llm.check`. `features/agent/llm.py`: `client(base_url, api_key)`
  (httpx, `TRANSPORT` подменяется в тестах), `check()` — `GET models` → 200,
  `normalize_base_url`, `DEFAULT_BASE_URL`/`DEFAULT_MODEL`.
- Модель `LlmCredential`: `base_url`, `model`, `api_key_enc`; провайдер отдельно
  не хранится.
- Фронтенд: каталог `shared/lib/llmProviders.ts` (deepseek/openai/openrouter/
  custom, `providerById`); провайдер-селект только в `SetupWizard.ModelStep`
  (нативная форма + `SelectField` + два `TextField`); в
  `pages/settings/ui/Settings.tsx` секция «LLM» — `base_url`, `model` с
  `datalist` из двух значений, ключ, «Проверить», «Удалить ключ».
- `tests/test_agent_llm.py` — существующие сценарии ключа/проверки;
  `tests/test_isolation.py` строит матрицу маршрутов из OpenAPI и сверяет
  ожидаемые коды/тела.
- antd-first (ТЗ R1.9): провайдер — `Select`, модель — `AutoComplete`
  (подсказки + свободный ввод id).
- Профиль: `verification` задачи включает backend-проверки, значит миграций
  нет (новых колонок не вводим).

## Шаги

### Бэкенд (backend-engineer)

1. `features/agent/llm.py`: новая `list_models(base_url: str, api_key: str) ->
   list[str]` — `client(...).get("models")`, при не-200 `LlmError("LLM model
   list failed: HTTP <code>")`, разбор `data[].id`, дедуп и сортировка по
   `id`. Ошибки httpx → `LlmError` (как в `check`).
2. `features/settings/service.py`:
   - `list_models(db, user, base_url: str, api_key: str | None)` — нормализует
     `base_url` (`normalize_base_url`, `ValueError` → 422), при пустом
     `api_key` берёт сохранённый (`LlmCredential` по `user.id`), иначе 400
     «LLM key is not configured»; делегирует в `llm.list_models`.
   - `set_llm(..., api_key: str | None)`: пустой/`None` → оставляем прежний
     `api_key_enc`; если записи нет — 400. `base_url`/`model` обновляются
     всегда.
3. `features/settings/routers/settings_llm.py`:
   - `LlmModelsIn {base_url: str(8..300), api_key: ApiKey | None = None}`,
     `LlmModelsOut {models: list[str], detail: str | None = None}`;
     `POST /api/settings/llm/models`: `LlmError` → 200 с `models=[]` и
     `detail` (как `/llm/check` не роняет UI), успех → `models`, `detail=None`.
   - `PUT /api/settings/llm`: `api_key: ApiKey | None = None`; ответ прежний
     (`masked` — маска сохранённого или присланного ключа, ключ не
     возвращается).
4. Тесты: новый `tests/test_settings_models.py` (MockTransport):
   список с провайдера; отказ провайдера → 200 + `detail`; `api_key=None` с
   сохранённым ключом; `api_key=None` без ключа → 400; `PUT` без ключа
   сохраняет прежний (`GET /llm` → тот же `masked`); `PUT` без ключа без
   записи → 400; чужой пользователь не видит ключ (`test_isolation`-стиль).
   `tests/test_isolation.py`: добавить `("POST", "/api/settings/llm/models")` в
   матрицу (ожидаемый код и тело по текущей конвенции файла).

### Фронтенд (frontend-engineer)

5. `shared/lib/llmProviders.ts`: `providerByBaseUrl(baseUrl)` (нормализация
   `trailing slash`, `custom` при отсутствии совпадения); экспорт
   `LLM_PROVIDERS`/`providerById` не ломаем.
6. `shared/api/index.ts`: тип `LlmModels {models: string[]; detail: string|null}`

7. Новый `shared/ui/LlmSettingsForm.tsx` (+ экспорт в `shared/ui/index.tsx`):

     `custom`), ключ (`TextField type="password"` `placeholder="sk-..."`,
     `autoComplete="off"`), модель (`AutoComplete` из antd: `options` из
     списка API, `allowClear`, свободный ввод);
   - загрузка списка: кнопка «Загрузить модели» + авто-запрос через 500 мс
     после изменения ключа/URL (не на каждое нажатие; `AbortController` не
     нужен — последний ответ выигрывает по `seq`);
   - фолбэк: ошибка → `Alert kind="warning"` с `detail` + статический каталог
     моделей провайдера; поле модели всегда доступно;
   - сохранение: `PUT` только с непустыми `base_url`/`model`; ключ можно не
     вводить (если `configured`), в подсказке — текущая маска;
   - режимы: `variant="wizard"` (кнопки «Проверить», «Сохранить», «Позже») и
     `variant="settings"` (статус подключения, «Удалить ключ» с confirm).
8. `app/SetupWizard.tsx`: `ModelStep` рендерит `<LlmSettingsForm
   variant="wizard" ... />`, сохранив контракт шага (`onSaved`, `onSkip`,
   `onCheck`).
9. `pages/settings/ui/Settings.tsx`: секция «LLM» → `<LlmSettingsForm
   variant="settings" ... />`; строка статуса (`base_url`/`model`/маска) и
   «Удалить ключ» остаются внутри компонента, остальные секции страницы не
   трогаем.
10. E2E: `viewer/e2e/settings-llm.spec.ts` — в настройках виден селект
    провайдера; выбор «Свой» показывает поле URL; `mockApi` отдаёт

    этого списка (проверка по `option` дatalist/antd-листа).

## Acceptance

  провайдера, при ошибке — каталог и ручной ввод; один компонент в онбординге
  и настройках; смена модели без повторного ввода ключа работает.
- A11 (часть): провайдер — antd `Select`, модель — antd `AutoComplete`, нет
  нативной формы.

  маску.

## Риски

1. **`api_key` стал необязательным** — изменение контракта. Матрица
   `test_isolation` строится из OpenAPI: обязательность поля там отражается,
   вносим правку осознанно и проверяем, что существующие вызовы с ключом
   проходят.
2. **Провайдер выводится из `base_url`** — при нестандартном URL (свой прокси
   на том же домене) пользователь увидит «Свой»; это допустимо, в подсказке
   показываем фактический `base_url`.
3. **Список моделей большой** (OpenRouter ~300) — `AutoComplete` виртуализирует
   список; не сортируем по алфавиту принудительно, сохраняем порядок провайдера.
4. **Гонка ответов** при быстром вводе ключа — отбрасываем устаревший ответ по
   счётчику.
5. **Секреты.** Ключ не логируем, не возвращаем, `detail` не содержит тело
   ответа провайдера (как `_error` в `llm.py`).
6. **Авто-запрос по паузе** может дёргать провайдера на каждом изменении
   URL/ключа; дебаунс 500 мс и только при непустом ключе.
