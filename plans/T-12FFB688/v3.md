# План T-12FFB688 — догон UI по макетам Graphite (v3: композер из DeepSeek-подхода, вложения из ФС)

## Контекст

Владелец сверил выпущенный интерфейс с макетами, которые предлагались при
планировании эпика, и нашёл расхождения. Макеты v2 (тёмная тема) приложены:

- `.tmp/design/out/mock-v2-home-dark.png` — Главная;
- `.tmp/design/out/mock-v2-settings-dark.png` — Настройки с блоком профиля;
- `.tmp/design/out/mock-v2-chat-dark.png` — Чат;
- `.tmp/design/out/mock-v2-fields-dark.png` — спецификация контролов и сетки
  секций (то, что сейчас «плывёт» на всех страницах).

Исходник макетов — `.tmp/design/mockup-v2.html` (рендер Playwright,
1440×960). Акцент на макетах показан синим для наглядности; в приложении акцент
остаётся пользовательским (по умолчанию графитовый).

### Что именно расходится (аудит)

1. **Главная** (`web/src/pages/home/ui/Home.tsx`):
   - заголовок — `PageHeader title="Главная"` (`Home.tsx:296`), нет приветствия
     по имени и сводки дня, как в макете;
   - действия в шапке — три ghost-ссылки «Задачи/Файлы/Календарь»
     (`Home.tsx:300-311`), нет «Задача» и «Спросить Atlas»;
   - KPI — 4 счётчика без спарклайнов (`Home.tsx:328-375`);
   - виджетов шесть (`Home.tsx:376,421,449,462,478,499`): нет «Ритма»
     (матрица привычек), «Сфер» с прогрессом и «Агент заметил» (сигналы).
2. **Настройки** (`web/src/pages/settings/ui/Settings.tsx`): блок «Профиль» —
   это JSON-редактор и сводка, без фото/логина/пароля/имени/возраста/города/рода
   деятельности. В `web/src/pages/profile/ui/Profile.tsx` есть фото и контекст,
   но не то, что ждёт владелец в настройках. Эндпоинта смены пароля нет:
   в `app/backend/features/auth/router.py` только `login/logout/me/avatar`.
3. **Чат** (`web/src/pages/chat/ui/Chat.tsx`):
   - «Новый чат» — вторичная кнопка (`Chat.tsx:682`), в макете — primary на всю
     ширину с «+»;
   - композер — `TextAreaField` + «Отправить» (`Chat.tsx:917-938`), нет
     прикрепления, `@документы`, чипа проекта и подсказки про Enter;
   - раскладка треда: сообщения и композер живут в одной панели, но вертикаль
     «шапка — лента — композер» не зафиксирована как в макете (композер
     опускается/поднимается в зависимости от контента).
4. **Поля и сетка (все страницы)** (`web/src/shared/ui/controls.tsx`):
   - высота контролов разная: у полей `min-height: 32px` (`controls.tsx:52`),
     у селекта `&& .ant-select { height: 32px }` (`controls.tsx:245`), у пикеров
     `height: 32px` (`PickerWrap`); при выборе значения в antd 6 контент
     `.ant-select-content` пересчитывается и строка «прыгает»;
   - подписи и подсказки в `FieldRoot` дают разный вертикальный ритм
     (`FieldRoot`/`FieldLabel`, `controls.tsx:133-146`);
   - строки форм (`Row`, `FormRow`) выравнивают кнопки/чекбоксы
     `align-items: end/center` непоследовательно — на скриншотах кнопка
     «Создать» ниже/выше поля;
   - отступы внутри панелей разнятся (`padding: 16` у `Panel` против `12/14` в
     секциях), из-за чего блоки «прилипают» к заголовкам.

## Шаги

**WS-1. Главная.**
1. Приветствие: `Доброе утро/день/вечер, {имя}` из `/api/me` (имя — из
   `profile.data.name`, иначе `username`), eyebrow с датой, сводка дня из
   реальных данных.
2. Действия: «Задача» (открывает форму новой задачи на Главной или ведёт на
   `/tasks#new` с фокусом), «Спросить Atlas» (переход в `/chat` с готовым
   промптом).
3. KPI со спарклайнами: данные только реальные (задачи по дням из
   `/api/tasks`, привычки из `/api/growth`, документы из `/api/documents`,
   фокус из событий); если ряда нет — спарклайн скрывается, цифра остаётся.
4. Виджеты: «Фокус дня» (уже есть), «Ритм» (матрица привычек с
   `/api/growth/habits`), «Последние документы» (`/api/documents?limit=5`),
   «Сферы» с прогрессом (сумма `tasks_done/tasks` по сферам одним запросом —
   без N+1), «Агент заметил» (сигналы из `/api/notifications`,
   `/api/agent/proposals`; пусто — виджет скрыт). Никаких выдуманных чисел.

**WS-2. Профиль в настройках.**
1. Блок «Профиль»: фото (существующий `POST /api/profile/avatar`), логин
   (read-only из `/api/me`), «Изменить пароль» — модалка + новый эндпоинт
   `POST /api/auth/password` (старый пароль, новый; bcrypt; тесты).
2. Поля «Имя, возраст, город, род деятельности» — типизированная форма поверх
   `profile.data` (без миграции БД), сохранение существующим `PUT /api/profile`.
3. JSON-редактор профиля убрать в «Дополнительно» (`Collapse`) — на случай
   ручных правок.
4. Убрать чекбокс «передавать контекст агенту» (если есть): агент всегда
   получает контекст профиля; удалить поле из модели/формы и из промпта сборки
   контекста, покрыть тестом.

**WS-3. Чат.**
1. «Новый чат» — primary на всю ширину с «+» (как в макете); панель списка
   диалогов: фиксированная шапка, скролл только у списка.
2. Композер — карточка-поле с фокус-рамкой и строка действий:
   - **вложения из файловой системы**: скрепка открывает выбор файлов на ПК
     (PDF/DOCX/TXT/MD, до 3 файлов, до 20 МБ), файлы загружаются существующим
     `POST /api/documents` (multipart, поле `file`), выбранные показываются
     чипами с удалением и состоянием загрузки; ошибка загрузки — тост;
   - **«Глубокий анализ»** — пилюля с иконкой (как в DeepSeek Chat), не серый
     antd-switch; значение уходит в `deep`;
   - справа — подсказка «Enter — отправить» и **круглая** кнопка со стрелкой
     вверх (во время стрима — та же круглая кнопка «Стоп»).
   Чип `@документы` не нужен: агент сам берёт документы приложения.
3. Раскладка: `thread` = шапка + лента (`flex:1; overflow:auto`) + композер
   (снизу, не «плавает»); панель списка — своя высота, скролл внутри списка.
4. **Выбор модели в окне — отдельная задача `T-0D6BFC5A`** (там же `meta`
   истории: метки «Глубокий анализ» и модель после перезагрузки). Здесь не
   реализуется, чтобы не конфликтовать по `Chat.tsx`.

**WS-4. Контролы и сетка секций (общий слой).**
1. Единая высота контролов 34px (`height`, `line-height`, `min-height`) для
   полей, селектов (включая `.ant-select-content` в antd 6), пикеров, кнопок.
2. `FieldRoot`: подпись 12px/1.2, gap 6, подсказка 11.5px; одинаковый ритм
   «подпись → контрол → подсказка/ошибка».
3. Строки: `Row` (кнопки/поля) — `align-items: end` при разнотипных контролах,
   `align-items: center` для чекбоксов/переключателей; правило зафиксировать в
   `shared/ui`.
4. Секции: `Panel` padding 16, `gap` заголовка 6, отступы между секциями 16;
   пройтись по всем страницам и убрать локальные `padding/gap`-хакеры.
5. Регресс: снапшот-спека контролов (`/dev`-страница не нужна — ручной прогон
   + a11y), e2e-селекторы не ослаблять.

## Риски

1. **Данные для виджетов**: «Ритм», «Сферы» с прогрессом и «Агент заметил»
   требуют данных, которых может не быть в API одним запросом. Правило:
   использовать существующие эндпоинты и скрывать виджет, а не выдумывать
   числа; N+1 не допускается.
2. **Новый эндпоинт смены пароля** — зона безопасности: bcrypt, проверка старого
   пароля, тесты в `tests/test_app_auth.py`, не логировать пароли.
3. **Удаление чекбокса контекста** может затронуть существующие сохранённые
   значения профиля — предусмотреть обратную совместимость (поле игнорируется).
4. **Вложения из файловой системы** используют существующий `POST /api/documents`:
   после загрузки в сообщение уходит `document_ids`; агент по-прежнему может
   взять документы приложения сам. Выбор модели и `meta` истории — в
   `T-0D6BFC5A` (после этой задачи).
5. **Геометрия контролов** трогает `shared/ui` и влияет на все экраны сразу:
   делать одним WS, после него прогнать все e2e/a11y и снять скриншоты
   ключевых страниц.
6. **Task-дубль**: при отладке флагов создана пустая задача `T-95866894`
   (scope `web/e2e/**`, без плана). Агент не может перевести её в `cancelled`
   (владельческое действие) — прошу владельца закрыть её.
