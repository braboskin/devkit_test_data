# План T-D9605E95 — история отметок привычек для матрицы «Ритм»

## Контекст

Виджет «Ритм» на Главной рисует 7-дневную матрицу, но `GET /api/habits` отдаёт
только `today` и `last_log` — остальные дни помечены «нет данных». Отметки при
этом **хранятся**: таблица `habit_logs` (`habit_id` + `date`, уникальная пара)
уже есть в `app/backend/features/growth/models.py`, пишется через
`POST /api/habits/{id}/log`. Нужен только способ отдать историю за период и
использовать её на фронте.

## Шаги

1. **Эндпоинт.** `GET /api/habits/history?days=7` (или `GET /api/habits?history=7`,
   совместимо расширив ответ) — по каждой привычке владельца список дат отметок
   за окно `[today - (days-1), today]`; days 1–31, по умолчанию 7; порядок
   привычек по названию, даты по возрастанию. Реализация в `repository.py`
   (один запрос, без N+1: `WHERE habit_id IN (...) AND date >= ...`),
   `service.py` собирает `{id, title, streak, today, dates: [...]}`.
2. **Схема.** Расширить `HabitOut` полем `dates: list[date] = []` (обратная
   совместимость: старое поле `last_log` остаётся).
3. **Фронтенд.** `web/src/pages/home/ui/Home.tsx`: матрица «Ритм» заполняется из
   `dates` (точка = отметка, сегодня — обводка), ячеек без данных больше нет;
   `web/src/shared/api/index.ts` — тип `Habit.dates`. Обновить `Caption`
   (убрать оговорку «API отдаёт только сегодняшнюю и последнюю отметку»).
4. **Тесты.** `tests/test_growth.py`: отметки за 3 дня → `dates` содержит те же
   даты; пустая история → `[]`; `days` вне диапазона → 422; чужие привычки не
   попадают. E2E: мок `/api/habits` с `dates` → в матрице видны отмеченные дни
   (не «нет данных»).
5. **Доступность.** У матрицы — `role="img"` и подпись «привычка: N из 7 дней»
   (как сейчас), у ячейки — `title` «отмечено»/«нет отметки».

## Acceptance

- Матрица «Ритм» показывает реальные отметки всех 7 дней; нет ложных «нет
  данных» для дней, где отметка есть.
- История отдаётся одним запросом, без N+1; чужие привычки недоступны.
- Профиль зелёный, e2e обновлён, axe 0.

## Риски

1. `habit_logs` может содержать отметки за пределами недели — фильтр по окну
   обязателен, иначе лишние данные.
2. Часовой пояс: `date` — локальная дата пользователя (`wallclock`), окно
   строить по тем же локальным датам, не по UTC.
3. Размер ответа: 7 дат на привычку — незначительно; при `days=31` всё ещё ок.
4. Если привычек много, матрица на Главной ограничена 5 строками (как сейчас) —
   это UI-решение, не менять.
