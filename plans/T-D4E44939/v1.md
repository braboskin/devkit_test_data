## Контекст

**Что уже есть:**

- M1: PostgreSQL/Alembic, модели §7 (users/sessions/spheres/projects/people/
  tasks/events), изоляция `owner_id`, вход, API, React-PWA (`viewer/**`).
- Прототипы знаний в `scripts/**`: `ingest.py` (MD/PDF/изображения → файлы
  `data/processed`, `data/meta`), `extract.py` (PyMuPDF + Tesseract),
  `chunking.py` (300–800 токенов, overlap 15%), `triage.py` (правила:
  тип/сфера/проект/policy/quality/summary), `index.py` (BGE-M3 dense+sparse →
  Qdrant), `retrieval.py` (RRF, rerank, логи), `search.py`, `eval.py`,
  `mcp_server.py`.
- Ограничения среды: Qdrant не запущен, `.qdrant` и кэш BGE-M3 отсутствуют,
  Docker на машине нет; `tests/fixtures/inbox` отсутствует, поэтому
  `ingest-fixtures` красный (не required).
- Профиль `unit-tests` зелёный (74 теста M1), `web-build`/`schema-check` зелёные.

**Цель M2:** загрузка документов через web; быстрый (VPS) и отложенный (ПК)
пути; очередь `jobs` и воркер `claim → heartbeat → complete/fail`; аннотации,
теги и сущности; гибридный поиск (BGE-M3 + PostgreSQL FTS, RRF) с обязательным
фильтром `owner_id`; похожие документы; архив оригиналов >20 МБ в Яндекс.Диске.
Acceptance: A3, A11; FR-4, FR-5, FR-15; изоляция A1 для новых маршрутов.

**Принятые допущения:**

1. Логика из `scripts/**` переезжает в `app/backend/knowledge/**`
   (extract, chunking, triage, entities, embeddings, search); `scripts/*`
   остаются тонкими CLI-обёртками с прежним поведением, тесты
   `test_ingest`/`test_chunking`/`test_triage` не ослабляются.
2. M2 без LLM: аннотация — экстрактивная (1–3 предложения), теги и сущности —
   правилами/regex, класс документа — эвристика по типу/пути/содержимому.
   Предложения (`proposals`) и LLM-аннотации — M3.
3. Тесты — SQLite + `QdrantClient(':memory:')` + детерминированная заглушка
   эмбеддингов; PostgreSQL FTS проверяется отдельным PG-тестом (skip без PG).
   Решение владельца (2026-11-21): на этой машине BGE-M3 не скачиваем, A3
   проверяется end-to-end на in-memory Qdrant с fake-эмбеддингами; реальная
   BGE-M3 — ручная приёмка владельца на его окружении.
4. Лимит файла — env `ATLAS_MAX_UPLOAD_MB` (default 100); быстрый путь PDF:
   ≤20 стр. и ≤20 МБ и есть текстовый слой; иначе `queued` + job.
5. Оригиналы — `data/storage/<owner_id>/<document_id>.<ext>` вне web-root;
   выдача только через авторизованный маршрут. Яндекс.Диск: токен в
   `integrations(owner_id, kind='yadisk', token_enc)`, шифрование Fernet
   (`ATLAS_FERNET_KEY`), маска в API/логах.
6. Воркер ПК — отдельный токен (хеш в `worker_tokens`), `FOR UPDATE SKIP
   LOCKED` на PostgreSQL; на SQLite в тестах — последовательный claim.
7. URL-приём: `http/https`, таймаут, запрет приватных адресов (SSRF), текст
   извлекается stdlib `html.parser`, без новых зависимостей.
8. Новые зависимости: `python-docx` (DOCX), `python-multipart` (уже стоит),
   `cryptography` (уже стоит) — фиксируются в `requirements.txt`.

**Открытые вопросы к владельцу (до/на approve):**
- A3 «документ находится» требует реальных BGE-M3 (~2.3 ГБ) и Qdrant. Разрешаешь
