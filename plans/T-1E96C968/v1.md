# План: Дерево проекта — поиск, фильтры, сортировка

## Контекст

Представление «Список» проекта группирует задачи по статусу, но без поиска и
фильтров. Данные уже загружены (`/api/tasks?project_id=`), поэтому фильтрация
клиентская; состояние — в URL.

## Шаги

1. `ProjectPage`: состояние `q`, `priority`, `sort` в URL
   (`?view=tree&q=&priority=&sort=`).
2. Панель над списком: `TextField` (поиск), `SelectField` (приоритет),
   `SelectField` (сортировка: по дате/приоритету/названию) на DS.
3. Фильтрация/сортировка в `buildTree`; счётчики групп после фильтра; пустое
   состояние «ничего не найдено» с кнопкой сброса.
4. Сохранить переключение видов; фильтры не влияют на доску/гант (там полный
   набор).

## Acceptance

- Поиск/фильтр/сортировка работают в «Списке», состояние в URL переживает
  перезагрузку.
- Пустой результат объяснён и сбрасывается.
- Проверки профиля зелёные.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web`.

## Scope

`viewer/src/pages/projects`.

## Риски

- Фильтрация только по загруженным задачам (проект грузит все свои задачи —
  приемлемо).
