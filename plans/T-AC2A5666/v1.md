# План S2c: Файлы, Настройки, уведомления, задания, поиск

## Контекст

- Каркас S0, бэкенд S1 в `main`: summary, медиа (аватар/фон/фото),
  `search?scope=all`, поля UI.
- Сейчас: `/files` → старый Documents, `/settings` — старый Settings,
  `/jobs` — старый Jobs, `/search` — старый Search с документами,
  `/notifications` — заглушка S0.
- ТЗ §6.11–6.12, 6.14–6.18; Acceptance A8, A9. API не меняется.

## Шаги

1. `pages/files`: дерево «интерес → проект → файлы» на `TreeList`,
   поиск/фильтры, сортировка по имени/дате, статусы обработки (бейджи),
   действия (открыть, скачать, переиндексировать, удалить), пустые состояния.
   Мобильный — drill-down по группам.
2. `pages/files/:id` (внутри слайса files): просмотр PDF/картинки/текста через
   `/api/documents/{id}/content` и `/file`, метаданные, статус и задание,
   действия, ссылка на исходный файл.
3. `pages/settings`: разделы — Профиль (ссылка), Внешний вид (`ThemePanel` +
   `uploadBackground`/`backgroundSrc`), Агенты (ссылка на
   `/settings/agents`), Интеграции (LLM и Яндекс.Диск — перенести существующую
   логику из старого Settings), Уведомления, Данные.
4. `pages/notifications`: лента `/api/notifications`, непрочитанные, отметка
   «прочитать» (`POST /{id}/read`), фильтр по типу, переход по `link`,
   включение push (существующий `shared/lib/push`).
5. `pages/jobs`: список `/api/jobs`, статусы, прогресс, отмена
   (`POST /{id}/cancel`), автообновление, пока идёт задание.
6. `pages/search`: результаты по группам через `searchAll` (задачи, проекты,
   интересы, люди, документы, чаты), «показать все», переход к сущности
   (`/files/:id` для документов); пусто/ошибка.
7. Переключить `app/router.tsx`; старые страницы не удалять.
8. Проверки и отчёт.

## Acceptance

- Файлы: дерево с группировкой, файл открывается по deep link, превью и статус
  видны, действия работают.
- Настройки: тема/акцент/фон (включая загрузку картинки), интеграции и
  уведомления работают как до переработки.
- Уведомления: непрочитанные и отметка прочитанного сохраняются.
- Задания: список и отмена работают.
- Поиск: группы из `scope=all`, документы по-прежнему находятся, из оверлея в
  шапке — то же поведение.
- Проверки профиля зелёные, старые страницы не сломаны.

## Проверки

`web-build`, `typecheck-web`, `lint-web`, `arch-web` — с exit code в отчёт.

## Scope

`viewer/src/pages/{files,settings,notifications,jobs,search}`,
`viewer/src/app/router.tsx`. Бэкенд, `shared/ui`, `package.json` — не трогать.

## Риски

- **Settings переносится почти целиком** — регресс интеграций; переносить
  логику без изменения API-вызовов, сверять по старому экрану.
- **Превью файлов**: содержимое и оригинал требуют cookie-сессию; `<img>`/PDF
  отдаются тем же origin — проверить в браузере.
- **Поиск**: группы пустые, если документы не проиндексированы; интерфейс должен
  объяснять пустоту, а не выглядеть сломанным.
- **Дерево файлов** грузит `/api/documents` целиком; при тысячах файлов нужен
  серверный фильтр — пометить ограничение в отчёте.
