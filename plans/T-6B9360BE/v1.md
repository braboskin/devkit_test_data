# T-6B9360BE — CI: Quality gates, UTF-8 вывод и сокращение набора тестов

План v1 (draft), 2026-11-27. Задача `T-6B9360BE` (chore/L), проект atlas.
Продолжение задачи T-3D35C25D, но отдельный scope: CI и тесты, без изменений
продуктового кода.

## Контекст

- Сейчас workflow называется `CI`, единственный job — `test`; шаги
  `Web build`, `Web typecheck`, `Web lint`, `Web architecture`, `Unit tests`,
  `Python lint`, `Python typecheck`, `Python architecture`. Имя job не говорит,
  что именно проверяется, статусы не разделены по платформам.
- `Unit tests` запускает `unittest discover -s tests`: 33 модуля, ~53 класса,
  446 тестов, ~4,5 минуты. Явного списка нет; часть модулей названа
  неоднозначно (`test_followup_acceptance`, `test_agent_scenario_runs`,
  `test_spheres_projects`, `test_worker_pg`), есть дублирующие acceptance-тесты,
  которые читают исходники viewer (`test_growth.ViewerAcceptanceTests`,
  `test_push.test_ab12_viewer_wiring`, `test_web_build.py`).
- Владелец сообщил, что в `Unit tests` русский текст отображается некорректно.
  В скачанном логе CI `пароль обновлён: alice` выглядит корректно (UTF-8),
  поэтому фиксируем политику явно: `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`,
  `chcp 65001`, и проверяем отображение в GitHub UI. Если кракозябры в другом
  месте (devkit web/локальный терминал) — фиксируем пример в отчёте.
- Решение владельца: разделить CI на джобы `web` и `python` в workflow
  `Quality gates`; добавить UTF-8; пересмотреть тесты — сократить/объединить
  не-критичные, имена привести к нормальным. Удаление тестов — только после
  утверждения владельцем списка кандидатов.
- Ограничения: поведение продукта/API не меняем; имена проверок devkit-профиля
  (`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `unit-tests`,
  `lint-python`, `typecheck-python`, `arch-python`) сохраняем; новых
  рантайм-зависимостей нет; миграции/`data/**`/`viewer/dist` не трогаем;
  self-hosted Windows runner один, джобы будут выполняться последовательно.

## Шаги

**S0. Инвентаризация тестов (read-only).** Собрать таблицу: модуль → класс →
число тестов → время → что проверяет → критичность (P0/P1/P2) → дубли/связь с
требованием. Замерить время по модулям (`unittest -v`/раздельные прогоны),
найти тесты, которые читают `viewer/src`/`viewer/dist`, и пересечения
(ingest/acceptance, agent, viewer). Результат — таблица в отчёте/PR с
кандидатами keep/merge/delete и обоснованием.

**S1. Политика критичности и список кандидатов — гейт владельца.**
Критерии:
- **P0 (оставить обязательно):** auth/ownership/isolation, миграции и схема,
  worker claim/lease/fencing, ingestion/documents (потеря данных, дедуп,
  очередь), agent tool-calls/proposals, tasks/events (RRULE, блокеры),
  search, arch-инварианты, web build smoke.
- **P1 (оставить или объединить):** notifications/push, yadisk/http_fetch,
  growth/onboarding, knowledge/chunking/triage, eval harness, PostgreSQL-тесты.
- **P2 (кандидаты на merge/delete):** дублирующие source-grep viewer-тесты,
  повторные acceptance-обёртки над уже покрытыми API-путями, вспомогательные
  тесты без инварианта.
Владелец утверждает список удаления/слияния (комментарий в devkit). До
утверждения тесты не удаляются и не отключаются.

**S2. CI: workflow Quality gates, джобы web/python, UTF-8.**
- `name: Quality gates`; jobs:
  - `web`: checkout → `npm ci` → `web-build` (`npm run build`) →
    `typecheck-web` (`npx tsc --noEmit`) → `lint-web` (`eslint .` +
    `prettier --check .`) → `arch-web` (`steiger ./src`) → upload artifact
    `viewer-dist` (path `viewer/dist`, `if-no-files-found: error`).
  - `python`: `needs: web`; checkout → venv/`requirements.txt` +
    `requirements-dev.txt` → download artifact в `viewer/dist` → `unit-tests`
    (`unittest discover -s tests`) → `lint-python` (`ruff check .` +
    `ruff format --check .`) → `typecheck-python` (`mypy`) → `arch-python`
    (`unittest tests.test_architecture`).
- Workflow env: `PYTHONUTF8: "1"`, `PYTHONIOENCODING: "utf-8"`;
  в Python-шагах `chcp 65001` (и `$OutputEncoding` при необходимости), чтобы
  русский вывод читался в GitHub UI.
- Имена шагов = имена проверок профиля; Tesseract, venv-кэш и проверки
  `$LASTEXITCODE` сохранить. При недоступности artifact на self-hosted —
  fallback: `npm ci && npm run build` в `python`-джобе (решение по факту).
- Проверить, что `test_web_build` не skip: `viewer/dist/index.html` существует
  в `python`-джобе; негативно — без artifact шаг должен падать, а не молча
  терять покрытие.

**S3. Сокращение и переименование тестов по утверждённому списку.**
- Объединить дубли: viewer source-grep acceptance → один
  `test_viewer_acceptance.py` (проверяет собранный dist/эндпоинты, а не
  исходники); ingest/acceptance-дубли — в доменные acceptance-модули.
- Переименовать модули по схеме `test_<domain>[_<kind>].py`, где kind —
  `unit|api|acceptance|integration|arch`; классы — `<Domain><Kind>Tests`.
  Убрать неоднозначные `followup`, `scenario_runs`, `spheres_projects`,
  `worker_pg` (→ `test_worker_postgres.py` и т.п.).
- Удалить только P2 из утверждённого списка; P0/P1 сохранить (можно
  объединить файлы без потери проверок).
- Обновить импорты/`mock.patch`-строки/ссылки в отчёте и AGENTS.md; полный
  `unittest discover` зелёный, число тестов и время зафиксировать.

**S4. Документация и качество.** В `repo/atlas/AGENTS.md`: политика
критичности тестов, схема имён, UTF-8 в CI, карта job/check. Обновить отчёт
`docs/reports/<id>.md`: инвентаризация, утверждённый список, до/после (файлы,
тесты, время), CI-логи. `devkit profile test` — verified; check-события на
финальном sha; `needs_review`.

**S5. Проверка CI вживую.** Push ветки/PR: оба джоба `web` и `python` зелёные,
артефакт скачивается, `unit-tests` выполняет `test_web_build` (не skip),
русский текст в логе читаем; статусы в GitHub раздельные. После `done` —
`devkit task ship --mode pr` (merge-commit).
