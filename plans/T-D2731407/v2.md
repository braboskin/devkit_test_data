# План T-D2731407 v2 — профиль пользователя, аватар и настройки без JSON

## Контекст

- `user_profile.data.context` (имя, возраст, город, профессия) пишут визард
  (`SetupWizard.tsx:545-596`) и `/profile` (`Profile.tsx:92-114`), но backend его
  **не читает**: в системный промпт попадают только `profile.summary` и
  `preferences.about` (`features/agent/context.py:149-160`). Отдельного хранилища
  контекста не нужно — поля переезжают на `users`.
- `User.display_name` есть в модели и `UserOut`, но **не устанавливается нигде**:
  CLI создаёт только `username`/`password_hash` (`app/backend/cli.py:59-64`),
  поэтому `display_name` у всех `NULL`. «Имя» в профиле = `display_name`, без
  дублирования с логином.
- Аватар: `POST /api/profile/avatar` (`features/auth/router.py:77-95`),
  `GET` (`:98-109`), удаления нет; `storage.delete` уже есть
  (`core/storage.py:96-99`). Клик по аватару и красный крестик требуют
  `DELETE /api/profile/avatar`.
- Auth: scrypt (`core/security.py:25-53`), cookie-сессии, есть
  `delete_user_sessions` для сброса других сессий (`cli.py:14`).
- Профиль агента: `system_message` собирает инструкцию, профиль, общий блок,
  scope (`context.py:141-192`). Строка владельца добавляется туда же, отдельного
  JSON-контекста нет.
- Тесты: SQLite + `Base.metadata.create_all` (`tests/test_app_auth.py:78-82`),
  миграция нужна для реального PostgreSQL. `test_app_auth` покрывает профиль и
  аватар, `test_isolation` — список эндпоинтов на изоляцию.
- Бриф T-7E446096 («Профиль (JSON) остаётся функционально тем же») устарел.
- Checkout `repo/atlas` занят T-59D31937 — работа в отдельном worktree от `main`.

## Цель

Поля профиля (логин, пароль, имя, фамилия, город, возраст, род деятельности)
живут на `users` и правятся через `PUT /api/me`; агент получает их в системном
промпте. `/profile` — карточка с аватаром-кнопкой и крестиком удаления, поля
справа на широком экране и ниже на мобильном, «Внешний вид» включает фон, без
нижней навигации. `/settings` остаётся без JSON-секции «Профиль».

## Шаги

1. **Миграция 0010** (`alembic/versions/0010_user_profile.py`): аддитивно
   `users.last_name String(120)`, `users.city String(120)`,
   `users.age Integer`, `users.occupation String(120)` — все nullable;
   `downgrade` убирает их. Модель `User` (`features/auth/models.py`) получает те
   же поля.
2. **Схемы** (`app/backend/schemas.py`): `UserOut` + новые поля; `MeIn` для
   `PUT /api/me` — `username` 3–64 (`[A-Za-z0-9._-]`), `display_name`/`last_name`/
   `city`/`occupation` ≤120, `age` 0–150, `password` 8–128, `current_password`
   обязателен только вместе с `password`.
3. **Сервис и роутер** (`features/auth/service.py`, `router.py`):
   `PUT /api/me` — частичное обновление; чужой `username` → 409; смена пароля
   только при верном `current_password` (403 иначе), после смены — scrypt-хеш и
   удаление **других** сессий пользователя; `DELETE /api/profile/avatar` —
   `storage.delete(avatar_ref)`, `avatar_ref = NULL`, идемпотентно (повторный
   вызов не падает), только свои данные.
4. **Промпт агента** (`features/agent/context.py`): после блока профиля —
   строка «Владелец: {display_name} {last_name}, {age}, {city}, {occupation}.»
   из непустых полей, каждое ≤120 символов; без данных строки нет.
5. **Viewer API** (`shared/api/index.ts`): `User` + новые поля, `updateMe`,
   `deleteAvatar`; тип `Me` в `Profile.tsx` убирается в пользу `User`.
6. **`/profile`** (`pages/profile/ui/Profile.tsx`): сетка
   `minmax(180px, 220px) 1fr` (≥760px), одна колонка ниже; аватар 96px —
   `<button type="button">` с доступным именем «Загрузить фото», скрытый
   `<input type="file">`, при `avatar_ref` — красная кнопка «×»
   (`aria-label="Удалить фото"`), после удаления — инициалы; справа форма:
   логин, пароль (поле «Текущий пароль» появляется, когда введён новый), имя
   (`display_name`), фамилия, город, возраст, род деятельности, «Сохранить».
   После сохранения — обновить `/api/me` и `SessionProvider` (добавить
   `refreshUser` в `App.tsx`/`session.tsx`), чтобы шапка и меню показали новое
   имя; ошибки 409/403 — человеческим текстом.
7. **«Внешний вид»** (`shared/ui/theme.tsx`, `Profile.tsx`): `ThemePanel`
   получает слот `extra` в блоке «Фон»; страница передаёт туда загрузку своей
   картинки и «Убрать фон». Секция «Фон страницы» и нижняя навигация удаляются.
8. **`/settings`** (`pages/settings/ui/Settings.tsx`): удалить секцию «Профиль»,
   `profile`-ресурс, `profileActions`, состояния `summary`/`profileData`/
   `profileError`, `saveProfile`, импорт типа `Profile`.
9. **Визард** (`app/SetupWizard.tsx`): шаг «О тебе» пишет имя/фамилию/город/
   возраст/деятельность через `PUT /api/me` (без чекбокса «Передавать контекст»);
   `data.context` больше не пишется; шаги и нумерация не меняются.
10. **Тесты**: `test_app_auth` — сохранение полей; 409 на занятый логин; вход
    новым логином; пароль без/с неверным `current_password` → 400/403, успешная
    смена, старая сессия не пускает, другие сессии удалены; DELETE аватара —
    200, `avatar_ref=null`, повтор идемпотентен, чужой аватар недоступен.
    `test_agent_onboarding` (или `test_agent_builder`) — строка «Владелец: …» в
    `system_message`, чужой профиль не течёт. `test_isolation` — новые методы.
    E2E: `/profile` рендерит поля, «Сохранить» шлёт `PUT /api/me`, крестик —
    `DELETE /api/profile/avatar` (mock).

## Acceptance

- **A1.** `alembic upgrade head` и `alembic downgrade -1` проходят на чистой
  PostgreSQL; `Base.metadata` и миграция совпадают; тесты SQLite зелёные.
- **A2.** `PUT /api/me` сохраняет поля; `GET /api/me` их возвращает; занятый
  логин → 409; смена пароля без текущего → 400, с неверным → 403, успешная —
  старый пароль не пускает, другие сессии разлогинены.
- **A3.** Клик по аватару загружает фото; «×» удаляет: `avatar_ref=None`,
  `GET /api/profile/avatar` → 404, повторное удаление идемпотентно.
- **A4.** В системном промпте есть «Владелец: Имя Фамилия, возраст, город,
  профессия»; у второго пользователя — только его данные.
- **A5.** `/profile`: две колонки на широком экране, одна на мобильном; нижней
  навигации нет; фон внутри «Внешнего вида»; `/settings` без секции «Профиль».
- **A6.** Визард сохраняет поля в `users`; `user_profile.data.context` не

- **A7.** Проверки зелёные, diff — только scope.

## Риски

1. **Auth — P0.** Смена логина/пароля ошибочно ломает вход: покрываем тестами
   вход старым и новым паролем, конфликт логина, изоляцию; текущий пароль
   обязателен, другие сессии удаляются.
2. **Миграция.** Только аддитивные nullable-колонки в `users`;
   `downgrade` — `drop_column`. Данные не переписываются.
3. **`display_name` пустой у существующих.** «Имя» показывается пустым, в шапке
   остаётся `username` — ожидаемо, заполняется пользователем или визардом.
4. **Потеря `data.context`** у существующих записей: не удаляем, просто не
   пишем; при необходимости разовый перенос — отдельным скриптом.
5. **Параллельные задачи.** T-59D31937 держит checkout (работать в worktree от
   `main`); T-7E446096 может тронуть `/settings` и `/profile` — при пересечении
   перебазироваться, его бриф устарел.
6. **Файл аватара.** Удаляем только `avatar_ref` своего пользователя; ошибка
   удаления файла не роняет запрос (`storage.delete` глотает).
