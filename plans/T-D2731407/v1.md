# План T-D2731407 — убрать секцию «Профиль» в настройках и мёртвый контекст профиля

## Контекст

- Секция «Профиль» на `/settings` — единственный потребитель сырого JSON
  `user_profile.data` + `summary` в UI
  (`viewer/src/pages/settings/ui/Settings.tsx:374-411`, состояние и
  `saveProfile` — `:77-131`, `:210-234`). Тестов на неё нет: e2e/a11y только
  открывают маршрут.
- Онбординг v2 (`viewer/src/app/SetupWizard.tsx`) пишет сущности в реальные
  таблицы: `POST /api/spheres` (`:634`), `createGoal` (`:721`), `createHabit`
  (`:794`), `createMetric` (`:866`), `putGrowthSettings` (`:932`).
- В `user_profile.data` остались: `context` (имя/возраст/город/профессия,
  пишут визард и `/profile`), `agent` {tone, depth}, `privacy`, `created`,
  `onboarding_done/_skipped`, `ui.background_ref`, `preferences.about`.
- Бэкенд читает только `summary` и `preferences.about` в системном промпте
  (`app/backend/features/agent/context.py:149-160`); `data.context`, `data.agent`,
  `data.privacy` не читает никто. `data.ui.background_ref` читает фон
  (`features/agent/service.py:727-735`), `onboarding_skipped` — баннер
  (`viewer/src/pages/home/ui/Home.tsx:53`).
- Карточка агента (scope, tools, instructions) — отдельный экран `/agents`;
  контекст per-agent уже собирается инструментами (`features/agent/tools.py`),
  профиль даёт только общий baseline. Поэтому `context` не «починить», а убрать.

## Цель

Удалить из UI мёртвый профильный блок: секцию JSON в настройках, форму
«Контекст для агента» и шаг «О тебе» визарда. Оставить профилю единственную
пользовательскую функцию — сводку «О владельце», которую агент получает в
промпте. Бэкенд, OpenAPI и данные существующих пользователей не меняются.

## Шаги

1. **Настройки** (`pages/settings/ui/Settings.tsx`): удалить секцию
   `profile-heading`, ресурс `api('/api/profile')`, `profileActions`, состояния
   `summary`/`profileData`/`profileError`, `saveProfile` и импорт типа `Profile`.
   Остальные секции (LLM, уведомления, Яндекс.Диск) не трогать.
2. **Профиль** (`pages/profile/ui/Profile.tsx`): вместо формы «Контекст для
   агента» (`:190-225`) — поле «О владельце» (`textarea`, `maxLength=4000`) с
   объяснением «используется в промпте всех агентов». Сохранение: `PUT
   /api/profile` с `data: profile.data?.data ?? {}` (ключи не терять) и
   `summary: trim() || null`. Удалить `Context`/`contextOf` и чекбокс
   «Передавать контекст агенту». Фото, фон, тема, ссылки — без изменений.
3. **Визард** (`app/SetupWizard.tsx`): удалить шаг `profile` из `STEPS`, ветку
   `step === 3`, компонент `ProfileStep`, `markCreated('profile')`; сдвинуть
   `move(N)` в цепочке (сферы=3, цели=4, привычки=5, метрики=6, ритм=7,
   агент=8, приватность=9). `SURVEY_FIRST` остаётся 3, `pathForStep`/
   `stepFromLocation` не меняются. `STORAGE_KEY` → `atlas.onboarding.v3`, чтобы
   сохранённый прогресс старой нумерации не открывал чужой шаг; повторный
   проход дублей не даёт — все шаги дедуплицируют по серверу
   (`:631-639`, `:710-718`, `:790-797`).
4. **E2E** (`e2e/onboarding.spec.ts`): deep link проверять на
   `/survey?step=1` → «Цели на квартал» (после удаления «О тебе» индекс 1 —
   цели, 0 — сферы); баннерный тест (`step=0`) не меняется.
5. **Отчёт** `docs/reports/T-D2731407.md`: что удалено, вывод проверок, что
   `data.context` больше не пишется; отметить отмену пункта брифа T-7E446096.

- **A2.** На `/profile` есть «О владельце», сохранение уходит в

   вручную.

   как делает визард; тест-подтверждение в A2.

   это ловит.
5. **Параллельная задача T-59D31937** занимает checkout `repo/atlas` (ветка
   `devkit/T-59D31937`, несохранённые файлы) — работать в отдельном worktree от
   `main` (`5c3511b`), чужие изменения не коммитить; если T-59D31937 уедет в
   `main` раньше — перебазироваться.
6. **Конфликт с брифом T-7E446096** («Профиль (JSON) остаётся функционально тем
   же») — пункт считать отменённым; если владелец против, план отклоняется.
