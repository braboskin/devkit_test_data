# План: Профиль — удаление фона и приоритет пресетов

## Контекст

Загруженный фон применяется инлайн-переменной `--bg-image` на `<html>` и
перекрывает пресеты темы; убрать фон из UI нельзя (в S1 есть только
`POST/GET /api/profile/background`).

## Шаги

1. Бэкенд: `DELETE /api/profile/background` — удалить файл из медиа-хранилища и
   поле `ui.background_ref` из профиля (идемпотентно: нет фона → 204).
   Логика в сервисе, роутер без прямых запросов к БД (arch-тест).
2. `shared/api`: `deleteBackground()`.
3. `pages/profile`: кнопка «Убрать фон» (показывать, если фон есть), после
   успеха — обновить профиль; подтверждение через `useConfirm`.
4. `app/AppShell`: если у профиля нет `background_ref` — снимать инлайн-
   переменную (`style.removeProperty('--bg-image')`), чтобы пресеты снова
   работали; при наличии — как сейчас.
5. Тесты: API «загрузил → удалил → ref пуст, файл недоступен» и идемпотентность.

## Acceptance

- Фон можно убрать из профиля; после удаления снова действуют пресеты темы.
- Повторное удаление — 204 без ошибок.
- Проверки профиля зелёные.

## Проверки

`unit-tests`, `lint-python`, `typecheck-python`, `arch-python`,
`web-build`, `typecheck-web`, `lint-web`, `arch-web`, `format-web`.

## Scope

`app/backend/features/profile` (или где живёт onboarding-роутер профиля),
`viewer/src/pages/profile`, `viewer/src/app/AppShell.tsx`,
`viewer/src/shared/api`, `tests/test_profile*.py`.

## Риски

- Поле `ui.background_ref` лежит в JSON `UserProfile.data`: правка должна
  сохранять остальные ключи (контекст, приватность).
- Удаление файла: если файла нет — не падать (идемпотентность).
