# План S1: бэкенд — миграции и эндпоинты под новый UI

## Контекст

- FastAPI, `features/*` (router → service → repository → models), SQLAlchemy 2,
  Alembic, mypy strict, ruff, arch-тесты. Профиль проверок в `devkit.yaml`.
- ТЗ `docs/tz/TZ-53B42870.md` §11 — таблица разрывов; Acceptance A10 и части A3,
  A5, A6, A8, A9.
- Сейчас: `Sphere(name)` без цвета; `Task(due_at)` без `start_at`/`progress`;
  `Project(due_at)` без `start_at`; `User(username, password_hash)` без
  `display_name`/`avatar_ref`; `Person` без фото; TZ — глобальная
  `ATLAS_TIMEZONE`; `/api/search` ищет только документы.
- `viewer/src/shared/api` — общий с S0: S0 создаёт клиент и типы-заготовки, S1
  добавляет функции. Поэтому задачи идут последовательно: S0 → S1.

## Шаги

1. Миграции Alembic (по одной на изменение, с откатом):
   - `spheres`: `color` (hex), `icon` (строка), `description`;
   - `tasks`: `start_at`, `progress` (0–100, default 0);
   - `projects`: `start_at`;
   - `users`: `display_name`, `avatar_ref`, `timezone` (nullable, fallback
     `ATLAS_TIMEZONE`);
   - `people`: `photo_ref`.
   Backfill: цвет по умолчанию из пресета, `progress = 0`, `display_name` из
   `username`.
2. Storage: загрузка аватара и фона — multipart, лимит размера и MIME, ресайз
   Pillow (аватар 256×256, фон ≤ 2048 по длинной стороне), хранение в каталоге
   владельца рядом с документами (`storage.py`), отдача через эндпоинт с
   проверкой владения. Ссылка в `User.avatar_ref` / `UserProfile.data.bg`.
3. Summary: `GET /api/spheres/{id}/summary` и `GET /api/projects/{id}/summary` —
   счётчики (проекты, задачи, люди, файлы), прогресс (задачи done/total),
   активность (последнее изменение). Сервисный слой, owner-фильтр в запросах.
4. Поиск: `GET /api/search?scope=all&q=` — группы `tasks`, `projects`, `spheres`,
   `people`, `documents`, `chats`; лимит на группу (по умолчанию 5), ILIKE по
   заголовкам/именам и `search()` по документам; `owner_id` в каждом запросе;
   ответ `{groups: [{type, items, total}]}`.
5. Слои: роутеры без `db.query`, логика в `service.py`, запросы в `repository.py`,
   если обращений больше одного. Межфичевых импортов не добавлять.
6. `viewer/src/shared/api`: функции и типы для новых эндпоинтов.
7. Тесты: изоляция (B не видит A) на каждый новый маршрут, ресайз и лимиты,
   summary на фикстурах, `scope=all` по всем группам, миграции вверх/вниз.

## Acceptance

- Миграции применяются и откатываются на чистой базе и на данных с записями;
  `schema-check` зелёный.
- Аватар и фон загружаются, режутся, отдаются только владельцу; чужой id — 404.
- Summary даёт корректные счётчики и прогресс на фикстурах.
- `scope=all` находит во всех группах, не смешивает пользователей, уважает лимит.
- Профильные проверки зелёные, arch-тесты не ослаблены.

## Проверки

`unit-tests`, `lint-python`, `typecheck-python`, `arch-python`, `schema-check` —
с выводом и exit code в отчёт.

## Scope

`app/backend`, `alembic/versions`, `tests`, `viewer/src/shared/api`. Вне scope:
`viewer/src/app`, `viewer/src/pages/*`, инфраструктура и деплой.

## Риски

- **Миграции на живых данных**: backfill цвета и `display_name` — в той же
  миграции, без падений на NULL; проверить на копии данных.
- **Pillow в запросе**: большой фон может подвесить воркер — лимит размера до
  ресайза, таймаут, 413 на превышение.
- **TZ**: колонка `timezone` nullable, fallback на `ATLAS_TIMEZONE`; напоминания
  переводятся на per-user TZ только там, где есть пользователь.
- **Поиск ILIKE** по большим таблицам: лимит на группу и `LIMIT` в SQL, без FTS в
  этой задаче.
- **owner-фильтр**: каждый новый маршрут — тест изоляции, иначе это P0-регресс.
