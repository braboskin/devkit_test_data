# План: Онбординг — маршруты /setup/*, deep links, баннер, идемпотентность

## Контекст

Поток онбординга живёт в гейте `App` → `SetupWizard` (11 шагов), прогресс — в
localStorage, deep-link на шаг невозможен; «Пропустить опрос» сразу завершает
настройку без баннера на Главной; id созданных сущностей не персистятся на
сервере (повторный проход после сброса localStorage может создать дубли).

## Шаги

1. Маршруты: `/setup/model`, `/setup/disk`, `/survey` (внутри `AppShell`-гейта
   не нужно — это pre-shell поток). `App` выбирает: не залогинен → `/login`;
   модель не настроена → `/setup/model`; диск не настроен → `/setup/disk`
   (пропуск хранится в профиле `data.skipped_disk=true`); опрос не завершён →
   `/survey`.
2. `pages/onboarding` (новый слайс-роут) рендерит шаги; `SetupWizard`
   становится движком шагов (или маршруты рендерят его с параметром шага).
   Deep link: `/survey?step=4&q=`; перезагрузка возвращает на шаг из URL,
   localStorage — только как резерв.
3. Баннер «Настройка не завершена» на Главной, если профиль без
   `onboarding_done`; «Пропустить опрос» ставит `onboarding_skipped=true` и
   баннер «Продолжить опрос» ведёт на `/survey?step=0`.
4. Идемпотентность: сервер хранит `UserProfile.data.onboarding_created`
   (ключи: sphere:<name>, goal:<title>, habit:<title>, metric:<name>); шаг
   «Утвердить» повторно не создаёт; ключ добавляется после создания.
5. Тесты: backend — повторный approve не дублирует; web — deep link возвращает
   на шаг; e2e-сценарий дополняется (пройти 2 шага, перезагрузить, шаг
   сохранился).

## Acceptance

- Прямая ссылка `/survey?step=N` открывает нужный шаг; после перезагрузки шаг
  тот же.
- Баннер на Главной появляется при пропуске и ведёт обратно в опрос.
- Повторное утверждение шага не создаёт дубликатов (проверено тестом).
- Поток целиком проходит без localStorage (по URL/профилю).
- Проверки профиля зелёные, e2e обновлён без ослабления.
