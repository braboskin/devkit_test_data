# M1: фундамент — PostgreSQL, изоляция, вход, сферы/проекты, люди, PWA-оболочка

Черновик плана v1. Регистрация через `devkit task plan` и старт работ — только
после утверждения ТЗ TZ-52EEACD7 (сейчас `draft`) и выдачи task-токенов.

## Контекст

**Что уже есть в Atlas** (repo/atlas @ `bc2126a`, проверено 2026-11-21):

- FastAPI-каркас `app/backend`: `create_app()`, SQLite по умолчанию через
  `ATLAS_DB_URL`, cookie-сессии на scrypt (HttpOnly, SameSite=Lax, TTL 30 дней
  без продления), `POST /api/auth/login|logout`, `GET /api/me`, `GET /health`;
  CLI `create-user|list-users|reset-password` с ролями owner/member.
- Baseline зелёный: `unit-tests` — 18 тестов OK (exit 0), `schema-check` —
  exit 0 (kb: 17 таблиц, 10 вьюх). Профиль `valid`.
- Ingestion, Qdrant, MCP, eval — в `scripts/**`; приложение их не использует.
- `docs/SCHEMA.md` — спроектированная схема `kb` (17 таблиц) **без** `owner_id`;
  это не модель §7 ТЗ.
- Нет: Alembic/миграций, psycopg, PostgreSQL в `docker-compose.yml`,
  `owner_id`, CRUD сфер/проектов/людей, тестов изоляции, фронтенда и PWA.
- В рабочем дереве repo/atlas — 118 файлов line-ending diff (CRLF); содержимое
  не меняется, коммитить его нельзя.

**Цель M1:** PostgreSQL-рантайм и миграции; `owner_id` и проверка владения на
каждом маршруте; вход по FR-1 (сессия 30 дней со скользящим продлением);
сферы/проекты (FR-3); люди (FR-17 частично: карточка и привязки к
сферам/проектам); PWA-оболочка (FR-13). Acceptance: A1 (реализованные
маршруты), A12 (оболочка), A17 (частично), A13.

**Принятые допущения** (подтверждаются этим планом):

1. Модель данных M1 — §7 ТЗ в схеме `public`: `users`, `sessions`, `spheres`,
   `projects`, `people`, `person_spheres`, `person_projects`. Спроектированная
   схема `kb` в `docs/SCHEMA.md` не трогается — она остаётся для знаний/метрик;
   последующие этапы добавляют свои миграции.
2. Два равноправных пользователя: поле `role` — только технический признак
   аккаунта администратора инсталляции, в API не отдаётся и на доступ к данным
   не влияет. Каждый запрос фильтруется по `owner_id = current_user.id`.
3. `users.id` — UUID (совместимо с текущим), id доменных сущностей — bigint
   identity (ТЗ: `allowed_spheres int[]`).
4. JSON-поля — `JSONB` на PostgreSQL и `JSON` на SQLite (SQLAlchemy variant),
   чтобы unit-тесты шли без внешнего PostgreSQL.
5. UI M1 — статическая PWA без сборки (HTML/CSS/JS), отдаётся тем же FastAPI;
   React/Vite на этом этапе не вводим.
6. Вне M1: события, задачи и участники (A17 полностью — M4); онбординг и агенты
   (M3); загрузка, поиск и Яндекс.Диск (M2).

**Готовность к старту:** ТЗ `draft`, плана нет, токена задачи нет. Код
начинается только после approve ТЗ в web, approve плана и выдачи токенов ролям.

## Шаги

Одна ветка: `devkit/T-2646A618` в `repo/atlas`. Коммиты — явными путями
(`git add <файлы>`), id задачи в сообщении; line-ending diff не коммитить.
Порядок: WS-A → (WS-B ∥ WS-C ∥ WS-D) → WS-E → WS-F.

| WS | Роль | Scope (файлы) | Зависит |

**1. WS-A «Фундамент».**
Добавить `psycopg[binary]` и `alembic` в `requirements.txt`; в
`docker-compose.yml` — сервис `postgres:17` с volume и healthcheck; в
`config.py` — `ATLAS_DB_URL` по умолчанию на PostgreSQL. Модели §7 (M1-подмножество)
с `owner_id` у всех доменных сущностей, FK и каскадами; заменить
`Base.metadata.create_all` на Alembic. Миграция `0001_m1`: таблицы, индексы
(`owner_id`), FK `person_spheres`/`person_projects` с `ON DELETE CASCADE`.
В `auth.py` — скользящее продление сессии (при активности продлевать до
`now + 30d`, не чаще одного апдейта в сутки). Убрать `role` из API-ответов и из
проверок доступа. Добавить общий `ownership`-хелпер (`get_owned_or_404`) и
`sessions` вместо `user_sessions`. В `create_app()` — монтаж `app/web` как
статики (`/`), если каталог существует. Создать пустые каркасы
`routers/{spheres,projects,people}.py` (`router = APIRouter(...)`) и подключить
их в `main.py`, чтобы WS-B/C не правили `main.py`. Тесты: `test_app_auth.py`
переписать на двух равноправных пользователей; `test_migrations.py` —
`alembic upgrade head` на временном SQLite + проверка таблиц, плюс PG-smoke
(временный кластер через `PG_BIN`/`C:\Program Files\PostgreSQL\17\bin`;
skip, если PostgreSQL не найден).

**2. WS-B «Сферы и проекты».**
`GET|POST /api/spheres`, `PATCH|DELETE /api/spheres/{id}`,
`GET|POST /api/projects`, `PATCH|DELETE /api/projects/{id}`. Все выборки — с
фильтром `owner_id`; чужой id → 404 (не 403); проект создаётся только в своей
сфере; удаление сферы с проектами → 409 со счётчиком; удаление проекта не
удаляет документы (документов в M1 нет). Тесты: CRUD, 404 на чужой id, 401 без
сессии, 409 при удалении связанной сферы.

**3. WS-C «Люди».**
`GET|POST /api/people`, `GET|PATCH|DELETE /api/people/{id}`,
`GET /api/people/{id}/relations`, `POST|DELETE /api/people/{id}/spheres|projects`
с ролью. Поиск/фильтры `?q=&sphere_id=&project_id=&tag=`. Контакты — только в
ответе владельцу, не в логах; заметки не логируются. Удаление человека
каскадно убирает связи (FK `ON DELETE CASCADE`), упоминания в документах —
позже (M2). Тесты: CRUD с контактами, привязки с ролью, карточка со связями,
поиск по имени, 404 на чужого человека, каскад при удалении.

**4. WS-D «PWA и UI».**
`app/web/`: `index.html`, `app.js`, `styles.css`, `manifest.webmanifest`,
`sw.js`, `offline.html`, иконки 192/512. Экраны M1: вход, список сфер/проектов,
список людей, карточка человека со связями и формами создания/привязки/удаления,
поиск по имени. SW: cache-first для оболочки, network для `/api/**`, офлайн —
`offline.html`. Тесты: `/` отдаёт index с manifest, manifest валиден и содержит
иконки/start_url, `/sw.js` отдаётся с корректным типом, офлайн-страница есть.

**5. WS-E «Изоляция и приёмка» (независимый test-engineer).**
`tests/test_isolation.py`: пользователь A создаёт сферу/проект/человека и
привязки, пользователь B не видит их в списках, получает 404 по id на GET/PATCH/
DELETE и на links-маршрутах; без сессии — 401. Плюс сценарий A17 (частично):
создание с контактами → привязка к сфере и проекту → карточка показывает связи
→ поиск находит по имени → удаление убирает связи. Документы, чаты, задачи,
события, цели, поиск, задания, уведомления в A1 попадут в M2–M5 — здесь их нет.

**6. Интеграция.** Дополнить `unit-tests` в профиле новыми модулями
(`test_migrations`, `test_spheres_projects`, `test_people`, `test_isolation`,
`test_pwa`); установить обновлённые зависимости в `.venv`; убедиться, что
`git status` в repo/atlas не содержит посторонних файлов и line-ending diff.

**7. Проверки, гейты, сдача.** Прогнать `unit-tests` и `schema-check`, записать
check-события с commit sha; гейты `code` и `test` — независимые роли, дополнительно
`architecture` и `security` (задача L требует четыре). Отчёт
`docs/reports/T-2646A618.md`, `devkit-team-sync`, затем `needs_review`. `done` —
только владелец; выпуск — по санкции.
