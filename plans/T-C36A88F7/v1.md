# План T-C36A88F7 — Повторение задачи: конструктор вместо RRULE-формулы

## Контекст

В форме задачи поле «Повторение (RRULE)» — свободный текст
(`FREQ=WEEKLY;BYDAY=MO`). Владелец просит выпадающие списки/мультивыбор
вместо формулы.

## Шаги

1. Конструктор: «Не повторять / Ежедневно / По будням / Еженедельно /
   Ежемесячно / Ежегодно» + интервал (`NumberField`), дни недели
   (`SelectField mode="multiple"`), «Заканчивается» — никогда / дата
   (`DateField`) / число повторов (`NumberField`).
2. Сериализация в RRULE и обратный разбор для редактирования; покрыть
   чистыми функциями в `web/src/shared/lib/rrule.ts` с юнит-тестами
   (Node-скрипт `node --test` или существующий e2e).
3. Предпросмотр «Следующие 3 раза» из уже установленного `rrule`-подобного
   решения на бэкенде — на фронте считать не обязательно: показываем
   человекочитаемую строку («Каждую неделю по пн и ср, 10 раз»).
4. Неподдерживаемые RRULE (из старых данных) — показывать как есть,
   с предупреждением и возможностью сбросить/сохранить.

## Acceptance

- все поддерживаемые бэкендом варианты собираются без ручного текста;
- редактирование существующей задачи сохраняет расписание;
- неподдерживаемый RRULE не теряется при сохранении без изменений;
- e2e на создание повторяющейся задачи, axe 0.

## Scope

- `web/src/pages/tasks/**`, `web/src/shared/lib/rrule.ts`,
- `web/src/shared/ui/**` (если нужна обёртка поля),
- `web/e2e/**`.

Бэкенд не меняем: формат `rrule` строкой остаётся.

## Проверки

Профиль проекта (все обязательные): `web-build`, `typecheck-web`, `lint-web`,
`arch-web`, `e2e`, `a11y`, `unit-tests`, `lint-python`, `typecheck-python`,
`arch-python`. **Профиль и CI теперь совпадают**: `lint-python` включает
`ruff format --check` (коммит `d7e5b99`), расхождение устранено.

## Риски

1. RRULE допускает конструкции, которые UI не выражает (BYMONTHDAY, BYSETPOS)
   — обязателен «расширенный» режим с текстом, но скрытый по умолчанию.
2. Смена расписания у существующей задачи может пересоздать события —
   убедиться, что бэкенд сохраняет поведение.
3. Часовой пояс и дата начала RRULE: конструктор не должен менять `dtstart`.
