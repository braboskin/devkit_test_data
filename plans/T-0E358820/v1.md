# M4 follow-up: технический долг напоминаний и push

## Контекст

Задача T-0E358820 (bug/M), эпик E-46E212B4, зависит от T-9F5FB3D3
(выпущена, merge `1baa23f` в `main`). Источник требований — комментарий
владельца `C-8cc4d65a7e` (brief карточки обрезан переносом строки) и раздел
«Риски» отчёта `docs/reports/T-9F5FB3D3.md`: R15, R4, R16, R13, R14, TTL,
тестовая гигиена, мелочи.

Проверено по коду `repo/atlas` на `main` @ `c3d4207` (рабочее дерево чисто,
сверху M4 уже есть `0007_job_priority`):

- **R15.** `pm.rrule_too_dense` оценивает плотность как
  `span * произведение BY-множителей / (период * INTERVAL)`. Для
  `FREQ=DAILY;BYDAY=MO,TU,WE,TH,FR,SA,SU` от 20 лет назад оценка 51 100 при
  фактических 7 300 вхождениях: серия молча пропускается сканером и expand.
  Причина — `BYDAY` для `DAILY` фильтрует, а не множит. Обратный класс —
  недооценка старых/плотных серий (BYWEEKNO/BYYEARDAY/BYSETPOS,
  совмещённые части), т.е. guard неполон в обе стороны.
- **R4.** `_AWARE_UNTIL = (?:Z|[+-]\d{2}:?\d{2})$` не ловит offset без минут:
  `validate_rrule("FREQ=DAILY;UNTIL=20261122T120000+03")` и `+3` проходят;
  `+0300`/`Z` — 422. Для задачи без `due_at` (`validate_rrule(rrule, None)`,
  `routers/tasks.py:_check_rrule`) такое правило сохраняется, а
  `next_occurrence → None`: напоминание молча теряется.
- **R16.** `propose_create_event` (`agent/tools.py:196`) не содержит
  `remind_minutes`, `_apply_create_event` (`agent/proposals.py:100`) его не
  пишет, хотя `Event.remind_minutes` существует. События из предложений
  агента никогда не напоминают.
- **R13.** Naive-время в БД = локальное настенное время сервера
  (`_naive_utc` в `pm.py`, `routers/events.py`, `routers/tasks.py`,
  `agent/proposals.py`; `datetime.now()` в `main.py` и
  `routers/notifications.py`). TZ сервера неявна: DST/перенос сервера меняет
  смысл сохранённых времён, тесты зависят от TZ машины.
- **R14.** `PushSubscriptionIn._endpoint` проверяет литералы и «почти-IP», но
  DNS-имена не резолвит (`settings_notifications.py:126-134`). `pywebpush`
  резолвит хост при отправке — TOCTOU/DNS-rebinding остаётся.
- **TTL.** У `notifications` нет очистки: таблица растёт без ограничения.
- **Тестовая гигиена.** `downgrade 0006` проверен только на SQLite;
  scheduler-тест (`test_ab17_scheduler_dispatches_and_stops`) поллит БД
  сном 0.05 с — тайминг-зависимый.
- **Мелочи.** `utcnow()`-дефолты у `Notification`/`PushSubscription`/
  `NotificationSettings` против `datetime.now()` в reminders; `DEFAULTS`
  продублированы в `reminders` и `settings_notifications` (разные ключи);
  комментарий `R14` вместо `R13` в `routers/notifications.py:68`;
  `PushPayload` в `viewer/src/api.ts:796` не используется; warning на
  hostile-строку пишется каждый тик.

Решения владельца (2026-11-23): **R13** — явная конвертация через
`ATLAS_TIMEZONE` без миграции; **R14** — allowlist push-хостов;
**TTL** — 90 дней для всех уведомлений.

## Цель

Закрыть перечисленный долг без новых зависимостей и без миграций: guard
плотности даёт корректный ответ в обе стороны, aware-`UNTIL` с любым offset
отвергается, события из предложений агента несут напоминание, время явно
привязано к настраиваемой TZ, endpoint подписки ограничен известными
push-сервисами, уведомления чистятся по TTL, тесты PG-downgrade и
scheduler-тест перестают быть условными/флейкими. Каждый пункт закрыт
регресс-тестом и явным наблюдаемым поведением.

**S4. R13 — явная TZ без миграции.** `app/backend/config.py`:

```python
def timezone() -> ZoneInfo | None:
    name = os.environ.get("ATLAS_TIMEZONE", "").strip()
    return ZoneInfo(name) if name else None

def now_local() -> datetime:
    zone = timezone()
    return datetime.now(zone).replace(tzinfo=None) if zone else datetime.now()

def to_wall(value: datetime) -> datetime:
    if value.tzinfo is None:
        return value
    zone = timezone()
    return value.astimezone(zone).replace(tzinfo=None) if zone else \
        value.astimezone().replace(tzinfo=None)
```

1. R13 — одна зона на инстанс (`ATLAS_TIMEZONE`), браузер и сервер в одной
   зоне; per-user/per-event TZ — отдельная задача, в этот scope не входит.
2. TTL — 90 дней, удаляются все уведомления (включая непрочитанные).
3. Allowlist по умолчанию: `fcm.googleapis.com`,
   `.push.services.mozilla.com`, `web.push.apple.com`,
   `.notify.windows.com`; env-override — для остальных.
4. Границы `remind_minutes` в предложениях те же, что у `EventIn`
   (0–525600).
5. Новые зависимости не добавляются; схемы БД и миграции не меняются.
6. План/отчёт в data-репозитории коммитит devkit; реализация — только в
   `repo/atlas` на ветке задачи.
