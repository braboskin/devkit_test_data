# План T-78AFCD0D — чат: поиск, «Стоп», «Глубокий анализ», вложения

## Контекст

- `app/backend/features/agent/routers/chats.py`: есть стриминг
  (`POST /api/chats/{id}/messages` → `StreamingResponse`), список/создание/удаление
  чатов, история и **отмена** `POST /api/chats/{id}/messages/{mid}/cancel`
  (`chat._cancelled`). `MessageIn` содержит только `content` — вложений и флага
  глубины в контракте нет.
- `viewer/src/pages/chat/ui/Chat.tsx` (после T-F4778357 будет на примитивах, с
  `Panel`, `SelectField`, шестерёнкой в `/settings/agents`): сейчас нет поиска по
  диалогам, кнопки «Стоп», переключателя «Глубокий анализ» и вложений.
- Список чатов уже грузится целиком (`GET /api/chats`) — поиск по нему не требует
  бэкенда.
- Требование исходного ТЗ эпика `E-AA7F23F1` §6.2; в задачу дизайн-перевода
  T-F4778357 не входило.

## Шаги

1. **Поиск по диалогам (фронтенд).** Поле поиска в шапке списка (`TextField`
   или `Input.Search` через `shared/ui`), фильтр по названию без учёта регистра и
   ё/е; пусто → `EmptyState` «Ничего не найдено»; счётчик найденного; сто̀ит
   завершать `Esc` и не терять выбор чата.
2. **«Стоп» (фронтенд, бэкенд уже готов).** Во время стрима в композере — кнопка
   «Стоп» вместо «Отправить»; обрывает `fetch` через `AbortController` и вызывает
   `POST /api/chats/{id}/messages/{message_id}/cancel` для текущего ответа
   (id брать из первого SSE-события); после отмены — статус «Остановлено» и
   перечитывание истории; ошибка отмены не блокирует отправку следующего
   сообщения.
3. **«Глубокий анализ» (фронтенд + контракт).** Переключатель в композере
   (antd `Switch`/`Checkbox` в строке над полем), значение уходит в
   `MessageIn.deep: bool = False`. Семантика по умолчанию (утвердить или
   заменить при ревью): при `deep=true` сервис увеличивает лимит контекстных
   фрагментов (топ-K ×2) и добавляет в system prompt инструкцию «разбирай
   альтернативы и ограничения, отвечай подробно»; в события ответа добавляется
   `meta.deep`, чтобы UI мог показать «Глубокий анализ включён». Отдельной модели
   не вводим — провайдер один.
4. **Вложения (контракт + фронтенд).** `MessageIn.document_ids: list[int] = []`
   (не больше 10, проверка владельца документа, отсутствующие id → 422).
   Контекст агента: фрагменты выбранных документов подмешиваются существующим
   `agent/context.py` с приоритетом выше обычного поиска, с лимитом токенов.
   UI: кнопка-скрепка в композере открывает `AutoComplete`/`Select multiple` по
   `GET /api/documents` (поиск по названию), выбранные документы — чипы с
   удалением, отправка передаёт `document_ids`.
5. **Тесты.** Бэкенд (`tests/test_agent_chat.py`): `deep=true` повышает лимит
   контекста (проверить по вызванному провайдеру через `MockTransport`);
   `document_ids` валидирует владельца (чужой документ → 422) и попадает в
   контекст; `cancel` идемпотентен. Матрица `tests/test_isolation.py` — новый
   контракт `MessageIn` не меняет маршруты, но проверить тела. E2E: поиск
   фильтрует список; «Стоп» доступен во время мок-стрима и возвращает композер;
   переключатель отправляет `deep`; выбор вложения показывает чип и уходит в
   тело запроса (проверяется мок-роутом).
6. **Доступность:** кнопки с `aria-label`, переключатель с `label`, чипы
   вложений удаляются кнопкой с `aria-label`, «Стоп» доступен с клавиатуры.

## Acceptance

- Поиск по диалогам фильтрует список, пустой результат — понятное состояние.
- «Стоп» прерывает стрим (визуально и на сервере через cancel), после отмены
  можно сразу отправить новое сообщение.
- «Глубокий анализ» переключается, флаг доходит до сервера и меняет контекст
  ответа; состояние видно в UI.
- Вложения: выбор существующих документов, чипы, передача `document_ids`,
  чужой документ отклоняется.
- Ключ и содержимое документов не попадают в логи/ответы сверх существующего
  контракта.
- axe (serious/critical) = 0 на `/chat`; e2e-сценарии выше зелёные.
- Поведение клавиш композера (Enter/Shift+Enter) и стриминг не сломаны.

## Риски

1. **Семантика «Глубокого анализа»** — продуктовое решение. В плане зафиксирован
   дефолт (больше контекста + инструкция); если нужно «другая модель» или
   «другой промпт» — правка плана до реализации.
2. **Вложения раздувают контекст** — лимит 10 документов и обрезка по токенам
   обязательны; при превышении — предупреждение в UI, а не тихое усечение.
3. **Отмена стрима** гоняется с серверным `_cancelled` (in-memory set): после
   рестарта сервера отмена не сработает для старых сообщений — допустимо,
   зафиксировать в отчёте.
4. **E2E со стримингом** требует мок-SSE (`ReadableStream` в `route.fulfill`),
   иначе тест станет флейки; таймауты не увеличиваем без причины.
5. **Совместимость контракта**: `MessageIn` расширяется необязательными полями,
   старые клиенты не ломаются; OpenAPI-матрица `test_isolation` проверяется.
