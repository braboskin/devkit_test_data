# ТЗ Graphite v2 — навигация-острова, тосты, проекты-дерево, календарь, формы

Эпик: **E-47FF66EB**. Основание: замечания владельца от 28.11.2026 после выпуска
эпика E-710FC7ED (дизайн-система Graphite и переименование фронтенда в `web/`).

## Контекст

Первый проход дизайн-системы выпущен полностью: токены, Emotion, Roboto Condensed,
примитивы `shared/ui`, все экраны на Graphite, удалён legacy CSS, фронтенд живёт в
`repo/atlas/web`. Второй проход закрывает накопившиеся расхождения с макетами и
три системные проблемы: стеклянные острова навигации, ошибки без видимой обратной
связи и непривычные механики (дерево проектов, календарь, конструктор повторений,
формы-модалки).

## Цель

После выпуска всех задач эпика интерфейс соответствует макетам v3, любая
ошибка видна пользователю (тост и локальная панель уведомлений), календарь
показывает события, а формы не заставляют прокручивать страницу.

Задачи эпика:

| ID | Тема |
| --- | --- |
| `T-6BD45D6E` | Навигация-острова LiquidGlass и верхняя панель из двух островов |
| `T-EBDB7D0F` | Тосты ошибок и локальная панель уведомлений |
| `T-20ECAACF` | Проекты: дерево по сферам с колонковыми фильтрами и сортировкой |
| `T-E12FC73C` | Календарь: показ событий и кнопка добавления |
| `T-C36A88F7` | Повторение задачи: конструктор RRULE вместо формулы |
| `T-7B422390` | Формы Людей и Агентов: модальное окно вместо нижней панели |

## 2. Общие требования (для всех задач)

- **R0.1. Только дизайн-система.** Стили — `@emotion/styled` и `var(--*)` из
  `web/src/app/styles/tokens.css`. Страницы не импортируют antd напрямую: antd
  доступен только через `shared/ui`. Новые обёртки добавляются в `shared/ui` лидом,
  не субагентами (избегаем конфликтов в общем файле).
- **R0.2. Доступность.** Один `h1` на экран, `aria-live` для асинхронных статусов,
  видимые фокус-кольца, клавиатурная доступность всех действий, axe (серьёзные и
  критичные) = 0.
- **R0.3. Нативных контролов нет.** Поля, списки, даты, переключатели — обёртки
  `shared/ui`. Для иконочных кнопок обязателен `aria-label`.
- **R0.4. Ошибки.** Любая пойманная ошибка API показывается тостом и попадает в
  локальную панель уведомлений (R1); inline-ошибки остаются только для валидации
  форм.
- **R0.5. Темы и ширина.** Проверяются обе темы (тёмная/светлая) и ширина 1440 и
  390 px; мобильная версия не ломается и не «съезжает».
- **R0.6. Никаких выдуманных данных.** Если данных для виджета/показателя нет — он
  скрывается, числа не подставляются.
- **R0.7. Проверки.** Все обязательные проверки профиля зелёные; e2e-селекторы не
  ослабляются; на каждую задачу — отчёт `docs/reports/<task>.md`.

## Требования

### R1. Тосты и локальная панель уведомлений — `T-EBDB7D0F`

- **R1.1.** Очередь тостов: уровни `success/info/warn/error`, стек снизу справа,
  автозакрытие (для ошибок — по клику или 8 с), `role="status"`/`role="alert"`,
  закрытие по Esc; тост не перекрывает поле ввода и композер чата.
- **R1.2.** Локальное хранилище уведомлений: `localStorage`, версия схемы, лимит 50
  записей, операции `add/read/dismiss/clear`, дедупликация по тексту ошибки и
  маршруту; закрытая запись не возвращается после перезагрузки; панель не делает
  серверных запросов.
- **R1.3.** Колокольчик в правом верхнем острове: счётчик непрочитанных, панель-остров
  со списком (тип, заголовок, текст, время), «Прочитать все», закрытие записи,
  пустое состояние; `aria-live` для счётчика.
- **R1.4.** Централизация: обёртка `api()` при ошибке добавляет ровно один тост и одну
  запись; локальные `catch` не дублируют её (явный «тихий» режим для мест, где
  ошибка уже обработана).
- **Acceptance:** любой неуспешный запрос даёт один тост и одну запись; «Прочитать
  все» обнуляет счётчик; закрытые записи не возвращаются; приватный режим браузера
  не ломает интерфейс (деградация в память).

### R2. Проекты: дерево по сферам с колонковыми фильтрами — `T-20ECAACF`

- **R2.1.** Дерево «сфера → проект» на существующей обёртке `TreeList` (antd `Tree`):
  уровень сферы с цветной точкой и счётчиком проектов, уровень проекта с названием и
  подписью; раскрытие/сворачивание сфер сохраняется между перезагрузками (URL или
  `localStorage`).
- **R2.2.** Колонки «Проект», «Статус», «Срок», «Прогресс». Сортировка по клику на
  заголовок колонки, `aria-sort`, стабильная сортировка; внутри сферы сортируются
  проекты, сферы — по названию; сортировка по умолчанию — по сроку.
- **R2.3.** Фильтр в колонке «Статус»: enum-мультивыбор (`входящие`, `активные`,
  `на паузе`, `выполненные`, `отменённые`) и режим **«Показать только»** /
  **«Скрыть»**; счётчики у значений; «Сбросить»; состояние в URL (`?statusMode=…&status=…`).
- **R2.4.** Поиск по названию сферы/проекта (без учёта регистра); пустые состояния:
  «нет проектов» и «всё скрыто фильтром» (с кнопкой сброса).
- **Acceptance:** фильтр и сортировка работают в обеих темах, состояние переживает
  перезагрузку, e2e на фильтр/сортировку, дерево не теряет `ProjectPage`-навигацию.

### R3. Календарь: показ событий и кнопка добавления — `T-E12FC73C`

- **R3.1.** Причина: в локальной БД 7 событий с владельцем — значит, дефект на
  фронтенде. Найти и починить в одном из трёх мест: диапазон `from/to` при запросе
  `/api/events`, маппинг `Event` → `EventInput` (`start/end/allDay`), передача событий
  в `CalendarGrid`. Зафиксировать причину в отчёте.
- **R3.2.** События отображаются в видах «Месяц», «Неделя», «День» и «Агенда»;
  повторяющиеся (`expand=true`) раскрываются, часовой пояс отображается локально.
- **R3.3.** Кнопка «Добавить событие» рядом с «Сегодня» (primary) открывает
  существующий диалог создания с текущей датой; созданное событие появляется сразу.
- **R3.4.** Регресс-тест e2e с моком `/api/events`: событие видно в месяце и неделе;
  без мока (живой стенд) — ручная проверка.
- **Acceptance:** события видны во всех видах, e2e-регресс падает при поломке,
  кнопка добавления работает с клавиатуры.

### R4. Конструктор RRULE — `T-C36A88F7`

- **R4.1.** Вместо свободного поля — конструктор: «Не повторять / Ежедневно /
  По будням / Еженедельно / Ежемесячно / Ежегодно», интервал (`NumberField`), дни
  недели (`SelectField mode="multiple"`), окончание: «никогда / до даты / число
  повторов».
- **R4.2.** Сериализация в RRULE-строку и обратный разбор для редактирования
  существующей задачи; человекочитаемый предпросмотр («Каждую неделю по пн, ср,
  всего 10 раз»).
- **R4.3.** Неподдерживаемые правила (из старых данных) не теряются: показываются
  как есть в «расширенном» текстовом поле (в `Collapse`), с предупреждением.
- **R4.4.** `dtstart`/часовой пояс не меняются при редактировании без изменения
  расписания; бэкендный контракт (`rrule` строкой) не меняется.
- **Acceptance:** e2e создаёт повторяющуюся задачу через конструктор; правка
  существующей сохраняет расписание; неподдерживаемое правило не теряется.

### R5. Формы Людей и Агентов: модальные окна — `T-7B422390`

- **R5.1.** Создание/редактирование человека и агента — в модальном окне `Modal` из
  `shared/ui`, а не выезжающей снизу панелью: заголовок, поля, футер
  «Отмена/Сохранить».
- **R5.2.** Поведение: закрытие по Esc и фону, фокус-ловушка, возврат фокуса на
  кнопку-открывашку, страница под модалкой не прокручивается; на мобильной ширине —
  максимум 90vh со скроллом внутри.
- **R5.3.** Валидация сохраняется: ошибки у полей, общая ошибка — тост; `useConfirm`
  для удаления.
- **R5.4.** Аудит остальных форм: если механика «выезжающая панель» встречается на
  других экранах — перевести их так же (список — в отчёте).
- **Acceptance:** модалка открывается поверх страницы, фокус возвращается, e2e
  «создать человека» и «создать агента» обновлены, axe 0.

### R6. Навигация-острова — `T-6BD45D6E`

- **R6.1.** Левый сайдбар — отдельный стеклянный остров (скругление 22, внутренний
  блик, тень). Внутри: бренд «Atlas» сверху, группы навигации, блок «Индекс знаний»,
  «Настройки» **отсутствуют** — вход через меню профиля и `Ctrl+K`.
- **R6.2.** Верхняя панель — два острова: **поиск по центру** (фиксированная ширина) и
  **профиль/уведомления справа** (аватар, колокольчик со счётчиком). Контент виден
  между островами, фон просвечивает.
- **R6.3.** Материал островов — выбранный владельцем вариант **«Графит»**:
  - тёмная тема: `--island-bg: rgba(13,15,19,.62)`,
    `--island-border: rgba(255,255,255,.07)`,
    `--island-highlight: rgba(255,255,255,.03)`,
    `--island-shadow: 0 18px 44px rgba(0,0,0,.5)`,
    `backdrop-filter: blur(26px) saturate(140%)`;
  - светлая тема: `--island-bg: rgba(255,255,255,.66)`,
    `--island-border: rgba(15,23,42,.08)`,
    `--island-highlight: rgba(255,255,255,.5)`,
    `--island-shadow: 0 16px 40px rgba(15,23,42,.12)`.
  - Блик намеренно тихий (3%), острова не должны выглядеть светлее фона.
- **R6.4.** `prefers-reduced-transparency` → непрозрачный fallback; мобильная ширина
  (<900): сайдбар сворачивается в иконки (или нижнюю панель на выбор реализации),
  острова не наезжают, поиск доступен.
- **R6.5.** Токены именованы `--island-*` и живут в `tokens.css`; никаких магических
  rgba по страницам.
- **Acceptance:** три острова (сайдбар + поиск + профиль), «Настройки» вне меню,
  axe 0, проверены обе темы и 390 px, `Ctrl+K` открывает поиск/палитру.

## 4. Поведение и данные (сводно)

- Новых серверных сущностей нет: уведомления — только браузер; фильтры/сортировка
  проектов — клиентские; конструктор RRULE сериализуется в существующую строку;
  модалки и острова — чистый фронтенд.
- Календарь использует существующий `/api/events?from=&to=&expand=true`; если корень
  дефекта окажется на сервере — правка `features/events/**` с тестами.
- Ошибки API — через централизованную обработку (R1), без разрозненных `ErrorNote`
  вне форм.

## 6. Порядок работ и зависимости

1. **Волна A:** `T-6BD45D6E` (каркас-острова) → `T-EBDB7D0F` (тосты/панель внутри
   нового каркаса) — последовательно, оба трогают `AppShell`.
2. **Волна B (параллельно):** `T-20ECAACF`, `T-E12FC73C`, `T-C36A88F7`,
   `T-7B422390` — непересекающиеся scope; `R3` начинается с диагностики дефекта.
3. Зависимость эпика: `T-EAD5B055` (rename) выпущен — пути `web/**`.

## 7. Риски

1. `backdrop-filter` на больших поверхностях — ограничить слоем острова, проверить
   прокрутку/GPU на слабом ноутбуке.
2. Режимы фильтра «показать/скрыть» легко перепутать: UI обязан явно показывать
   текущий режим и счётчики.
3. Календарь: часовой пояс и диапазон дат — фиксировать UTC-событием в тесте.
4. RRULE: конструктор не выражает все конструкции (BYMONTHDAY/BYSETPOS) — нужен
   «расширенный» режим, иначе данные теряются.
5. localStorage может быть недоступен/переполнен.
6. Модалки: блокировка прокрутки body и возврат фокуса — частая регрессия.
