# ТЗ: Atlas — второй мозг с агентом-помощником (v1)

Статус: черновик v0.6 (на согласование владельцу)
Задача: T-78E09960
Дата: 2026-11-21

## Цель

Atlas — приватное веб-приложение (PWA) для двух пользователей. Пользователь
загружает документы, ведёт проекты, задачи, календарь, цели, привычки и метрики,
а агент помогает: отвечает по базе, ведёт обзоры, предлагает изменения и
следит за состоянием дел. Пользователь курирует агента: агент только
предлагает, изменения применяет пользователь. Данные пользователей не
пересекаются.

Цель: «второй мозг» — не склад файлов, а система, которая помнит, находит,
напоминает и помогает развиваться.

## Контекст

Atlas уже содержит: ingestion (MD/PDF/изображения), импорт Obsidian, triage,
чанкинг, Qdrant `kb_chunks` (BGE-M3 dense+sparse), гибридный поиск с RRF и
rerank, eval, MCP-сервер, FastAPI-каркас с cookie-аккаунтами на SQLite.
Спроектирована PostgreSQL-схема (17 таблиц) и координация эпиков, включая
EP-011 (Agent Chat) и EP-012 (Telegram). Код приложения пока не использует
PostgreSQL, Qdrant не запущен, корпуса нет.

ТЗ расширяет продукт до «второго мозга»: PostgreSQL-рантайм, две изолированные
учётные записи, агент с инструментами, PM, календарь, развитие, проактивные
обзоры, PWA и push. Telegram отложен.

Вне v1: Telegram, внешние интеграции календаря (синк), финансы, тренировки/
импорт из трекеров, шеринг, мобильные нативные приложения.

## 2. Пользователи, доступ, онбординг

- Два аккаунта: `owner` (администратор) и `member`. Полная изоляция данных.
- Регистрации нет: аккаунты создаёт владелец через CLI; вход — логин/пароль,
  cookie-сессия (scrypt, HttpOnly, SameSite=Lax, Secure на HTTPS).
- **Онбординг**: при первом входе агент проводит интервью (10–15 вопросов,
  адаптивно): сферы, активные проекты, цели, привычки, распорядок, ограничения,
  предпочтения по стилю. Результат — `user_profile` (структурированный JSON)
  + сводка. Профиль редактируется, используется агентом в контексте.
  Онбординг можно прервать и продолжить. Дальше профиль уточняется по мере
  работы: агент задаёт вопросы, а не додумывает отсутствующие данные.
- Каждый пользователь задаёт свой LLM-ключ (base_url, model, api_key) и свой
  токен Яндекс.Диска. Ключи шифруются, в API/логах маскируются.
- Изоляция: `owner_id` у всех сущностей, фильтр в Qdrant, проверка владения в
  каждом маршруте. Общих сфер, проектов, документов, чатов и уведомлений нет.

## 3. Домен

- **Сфера** — плоский верхний уровень (без вложенности): «Здоровье», «Работа».
- **Проект** — принадлежит одной сфере; статус, описание, срок, прогресс.
- **Человек** — отдельная сущность: имя, контакты, роль/отношение, заметки,
  теги. Участвует в сферах и проектах (с ролью), в событиях (участник) и
  упоминается в задачах. Не путать с учётной записью: `member` — пользователь
  приложения, человек — запись о персоне в базе.
- **Документ** — файл или URL; сфера, опционально проект; статус обработки,
  аннотация, извлечённый текст, теги, сущности, связи.
- **Задача** — проект/сфера, статус (`todo/doing/done/cancelled`), приоритет,
  срок, подзадачи, зависимости, повторение (RRULE), теги; может ссылаться на
  людей (ответственный, участник, «жду ответа»).
- **Событие** — календарь: начало/конец, весь день, место, описание,
  повторение, напоминание за N минут; участники — люди с ролью.
- **Цель** — критерий достижения, срок, прогресс, привязка к сфере/проекту.
- **Привычка** — периодичность, цель на период, отметки выполнения.
- **Метрика** — конструктор: название, тип (число/шкала/да-нет), единица,
  частота; ручные записи и график.
- **Дневник** — записи рефлексии; еженедельный обзор агента.
- **Агент (персона)** — настраиваемый помощник: имя, роль, инструкция, доступ к
  сферам/проектам, набор инструментов, модель. Вызывается из чата. Виден в UI.
- **Внутренний сабагент** — агент без чата и без своего места в UI: вызывается
  другим агентом через делегирование (проверка черновика, редактирование текста).
  Наследует доступ родителя, не имеет своего ключа, не создаёт историю чатов;
  вызов виден только в трейсе агента.
- **Сценарий** — сохранённый шаблон запроса агента с параметрами (например
  «разбери анализы за период», «сводка по проекту»); одношаговый в v1.
- **Чат** — диалог с выбранным агентом; общая история для web/PWA.
- **Предложение агента** — карточка изменения (`proposal`), применяется
  пользователем.
- **Задание обработки** — отложенная работа воркера на ПК.
- **Уведомление** — in-app + push.
- **Профиль** — данные онбординга и предпочтения.

## 4. Сценарии

UC-1. Первый вход: онбординг-интервью → профиль → агент приветствует с
коротким планом на неделю.

UC-2. Загрузка: файл → выбор сферы/проекта или «Входящие»; малый текстовый PDF
обрабатывается сразу; книга/скан — задание на ПК.

UC-3. Вопрос: агент ищет по данным пользователя, отвечает с цитатами;
при неоднозначности уточняет.

UC-4. Ведение дел: пользователь просит «запланируй подготовку к экзамену» —
агент предлагает проект/задачи/события, пользователь применяет карточки.

UC-5. Утро: push и экран «Сегодня» — события, задачи, что нового; вечер —
итоги. Неделя — обзор прогресса и рекомендации.

UC-6. Развитие: агент задаёт вопросы рефлексии, предлагает цели и привычки,
показывает метрики.

UC-7. Календарь: событие создаётся вручную или из предложения агента; кнопка
«Добавить в Apple Calendar» отдаёт `.ics`.

UC-8. Удаление: документ/чат/проект удаляет только пользователь; агент
показывает предложение и последствия.

## Требования

### FR-1. Аутентификация
- Вход/выход, `/api/me`, сессия 30 дней со скользящим продлением.
- Единый ответ на неверный логин; защита всех прикладных маршрутов.

### FR-2. Онбординг и профиль
- Чат-интервью с адаптивными вопросами; ответы можно править.
- Профиль: сферы, проекты, цели, привычки, распорядок, ценности, ограничения,
  стиль общения. Хранится структурированно, отдаётся агенту.
- Повторный пересмотр профиля по запросу пользователя и по предложению агента.

### FR-3. Сферы и проекты
- CRUD; проект в одной сфере; архив; прогресс проекта (задачи/цели).
- Перемещение проекта между сферами, документа — между проектами.
- Удаление — только пользователем, с подтверждением и предупреждением о
  связанных данных.

### FR-4. Документы и обработка
- Приём: PDF, DOCX, MD/TXT, изображения, URL. Лимит файла — настройка
  (по умолчанию 100 МБ).
- Дедупликация по sha256 в рамках пользователя.
- Быстрый путь: PDF с текстовым слоем ≤ 20 стр. и ≤ 20 МБ — текст и индексация
  сразу на VPS.
- Отложенный путь: сканы, изображения, большие PDF — задания `extract` /
  `extract-full` на ПК; для больших PDF допускается аннотация по метаданным
  (название, автор, страницы, оглавление, первая страница, класс).
- Статусы: `uploaded → processing/queued → ready | needs_review | failed`.
- Аннотация: 1–3 предложения + класс + ключевые сущности.
- Автоматические теги и сущности (люди, организации, места, даты) — сразу.
- Классификация по сфере/проекту при уверенности ≥ 0.7; ниже — предложение.
- Кнопки: переобработать, открыть оригинал, скачать.

### FR-5. Поиск
- Семантический (BGE-M3 на VPS для запроса) + полнотекстовый (PostgreSQL FTS).
- Фильтры: сфера, проект, тип, класс, дата, статус, теги.
- Гибрид dense+sparse + RRF; rerank — v1.1.
- Похожие документы (near-duplicates) — v1.
- Qdrant-фильтр по `owner_id` обязателен.

### FR-6. Чат и агент
- Чат создаётся с выбранным агентом (по умолчанию — «Универсальный помощник»);
  агент видит только разрешённые ему сферы/проекты и данные своего владельца.
- Агент: любой OpenAI-совместимый endpoint (старт — DeepSeek), ключ пользователя.
- Инструменты чтения: `search`, `get_document`, `list_spheres`, `list_projects`,
  `list_documents`, `list_tasks`, `list_events`, `list_goals`, `list_people`,
  `get_person`, `stats`.
- Инструменты-предложения: `propose_create_task`, `propose_update_task`,
  `propose_create_event`, `propose_create_goal`, `propose_move_document`,
  `propose_set_tags`, `propose_create_sphere/project`, `propose_delete`,
  `propose_merge_duplicates`, `propose_structure_change`,
  `propose_create_person`, `propose_link_person`, `propose_merge_people`.
- Агент **не выполняет изменения**: возвращает `proposal`; UI показывает
  карточку «Применить / Отменить»; применение — действие пользователя.
- Ответ с цитатами (документ + фрагмент), стриминг SSE, отмена генерации.
- Контекст агента: профиль, активные цели/проекты, задачи на сегодня,
  события, свежие документы, результаты поиска.
- При нехватке данных агент задаёт уточняющий вопрос и не выдумывает факты,
  даты, значения и связи; в ответе помечает, чего не хватает.
- Без ключа LLM чат и агент недоступны с подсказкой; загрузка/поиск работают.

### FR-7. Предложения и кураторство
- `proposal(id, owner_id, kind, payload, status pending|applied|rejected,
  created_at, applied_at, undo_until)`.
- Применение — атомарно, с записью в audit; для перемещений/тегов — undo
  5 минут.
- Деструктивные предложения (удаление, объединение) — обязательное явное
  подтверждение, повторная проверка владения при применении.

### FR-8. PM (задачи)
- Задачи: статусы, приоритет, срок, теги, проект/сфера, описание.
- Подзадачи (дерево), зависимости (`blocked_by`), повторяющиеся (RRULE).
- Доска по статусам и список; фильтры; сортировка по сроку/приоритету.
- «Просроченные», «на сегодня», «без движения».
- Агент предлагает задачи/подзадачи/сроки; создаёт пользователь.

### FR-9. Календарь
- События: дата/время, весь день, место, описание, повторение, напоминание.
- Представления: месяц, неделя, день; сфера/проект — фильтры.
- Напоминания: push и in-app за N минут (настройка).
- «Добавить в Apple Calendar»: отдача `.ics` для события; подписка (webcal)
  на календарь сферы/проекта — сразу, с токеном подписки.
- Агент предлагает события; создаёт пользователь.

### FR-10. Развитие
- Цели: критерий, срок, прогресс, сфера/проект; история изменений.
- Привычки: периодичность, цель, отметки, серии.
- Метрики: конструктор (число/шкала/да-нет, единица, частота), записи,
  график, сравнение периодов.
- Дневник: запись в свободной форме; агент задаёт вопросы рефлексии.
- Еженедельный обзор: прогресс по целям/привычкам/метрикам, рекомендации.

### FR-11. Проактивность
- Задания: `review.daily`, `review.weekly`, `triage.inbox`,
  `audit.duplicates`, `audit.structure`, `nudge.stale`.
- Планировщик создаёт задания по расписанию; воркер/LLM формирует обзор или
  предложения; результат — уведомление и карточки.
- Настройки: ритм (утро/вечер/неделя), тихие часы, максимум push в день.
- Агент только предлагает; напоминания — уведомления.

### FR-12. Уведомления и push
- In-app лента + бейдж; категории: обработка, задания, обзоры, напоминания.
- Web Push (VAPID): подписка в PWA, сервер шлёт по событиям; iOS — только для
  установленной PWA.
- Настройки категорий и тихих часов; отписка.

### FR-13. PWA
- Манифест, установка, mobile-first, офлайн-оболочка и последние 20
  документов/чатов; запись и обработка требуют сети.
- Без нативных приложений.

### FR-14. Экспорт и данные
- Экспорт документа (оригинал/текст/MD), чата, задач/событий/целей.
- Полный экспорт аккаунта — v1.1; удаление аккаунта со всеми данными — v1.1.

### FR-15. Яндекс.Диск (v1)
- Токен у каждого пользователя; оригиналы > 20 МБ выгружаются в
  `/atlas/<document_id>.<ext>`; на VPS — текст, аннотация, ссылка.
- Нет токена — оригиналы на VPS в пределах лимита.
- Удаление документа пытается удалить облачный оригинал; ошибка — в лог.

### FR-16. Кастомные агенты и сценарии
- Конструктор агента: имя, роль, инструкция, доступ (сферы/проекты), набор
  инструментов, модель, температура, пометка о предметных ограничениях.
- **Пользовательские агенты (13, доступны сразу):** «Универсальный помощник»,
  «Библиотекарь», «Секретарь», «Наставник», «Врач», «Тренер», «Финансист»,
  «Исследователь», «Юрист», «Учитель», «Психолог-рефлексия», «Путешественник»,
  «Аналитик».
- **Внутренние сабагенты (2):** «Критик» — проверяет черновик ответа/плана на
  противоречия, опасные советы и пропущенные данные; «Редактор» — улучшает
  структуру и формулировки текста. В UI не показываются, чатов не имеют.
- Делегирование: агент вызывает сабагента инструментом `ask_critic` /
  `ask_editor`; вызов синхронный, результат возвращается родителю. Сабагент
  наследует доступ родителя (allowed_spheres/projects), работает на ключе
  владельца и не пишет в историю чатов; вызов сохраняется в `agent_calls`
  (родитель, результат, токены) для трейса.
- Включение: флаги `use_critic` / `use_editor` у агента; для «Врача», «Юриста»
  и «Финансиста» `use_critic` включён по умолчанию.
- Проверка агента: тестовый вопрос в редакторе, без записи в историю чатов.
- Агент не видит данные вне разрешённых сфер/проектов: ограничение
  применяется в инструментах и в поиске, а не только в промпте.
- Сценарии — **многошаговые**: шаг = инструкция + параметры + ожидаемый
  результат. Шаги выполняются последовательно, состояние сохраняется,
  сценарий можно приостановить, продолжить и отменить; изменения — только
  через `proposal` и подтверждение.
- Примеры сценариев: «Разбор анализов» (найти документы → извлечь показатели →
  сравнить с предыдущими → вопросы врачу), «Подготовка к встрече» (контекст →
  повестка → событие), «Разбор книги» (оглавление → конспект → тезисы → задачи),
  «Недельный обзор» (метрики → цели → рекомендации).
- Вызов агента: селектор при создании чата; чат помнит агента. Сценарий
  запускается из чата, с «Сегодня» и из карточки агента.

### FR-17. Люди
- CRUD: имя (обязательно), контакты (телефон, email, мессенджеры), дата
  рождения, роль/отношение («врач», «коллега», «семья»), заметки, теги.
- Привязки с ролью: человек ↔ сфера, человек ↔ проект, участник события,
  ссылка из задачи (`responsible`, `participant`, `waiting`).
- Карточка человека: связи (сферы, проекты), события, задачи, упоминания в
  документах; быстрый переход к связанным сущностям.
- Поиск и фильтры: по имени/контактам/тегам, по сфере/проекту; список людей.
- Распознанные в документах сущности-люди связываются с карточками только
  предложением (`proposal`), не автоматически; дубликаты предлагаются к
  объединению.
- Удаление — только пользователь; связи удаляются, упоминания в документах
  остаются как текст.
- Приватность: контакты доступны только владельцу, не попадают в Qdrant и
  логи; карточка человека не индексируется как документ.
- Агент: `list_people`, `get_person`, `propose_create_person`,
  `propose_link_person`, `propose_merge_people`; создание и связывание — только
  через подтверждение.

## 8. Воркер (ПК)

- Исходящий HTTPS к VPS, токен воркера, `claim → heartbeat → complete/fail`.
- Захват атомарный (`FOR UPDATE SKIP LOCKED`), без Celery/Redis.
- Задания: `extract`, `extract-full`, `index`, `classify`, `summarize`,
  `review`, `audit`, `triage`.
- ПК офлайн — задания ждут без TTL; отмена пользователем; повтор вручную.
- Локальная модель (Ollama) — для отложенных LLM-задач; адрес настраивается.

## Ограничения

- VPS 4 ГБ RAM минимум (BGE-M3 + PostgreSQL + Qdrant + API), 8 ГБ
  рекомендуется; HTTPS + домен, API не открыт наружу.
- Изоляция: тесты «B не видит A» на каждый маршрут и на поиск.
- Секреты: шифрование at rest, маска в API/логах, не в git.
- Загрузки: проверка MIME/размера, uuid-имена, вне web-root.
- Первый токен ответа ≤ 8 с при доступном LLM.
- Бэкапы: PostgreSQL + Qdrant-снапшот + оригиналы, ежедневно; проверка restore.
- Наблюдаемость: `/health`, структурные логи, статус очереди/воркера.
- Предметные советы: медицинские, юридические и финансовые ответы агента
  сопровождаются пометкой из профиля агента (`safety_note`): «не заменяет
  специалиста»; агент не ставит диагноз, не назначает лечение и не даёт
  гарантий по сделкам.
- Персональные данные людей (контакты, заметки) — только владельцу: не
  индексируются в Qdrant, не пишутся в логи, маскируются в отчётах; экспорт
  и удаление — по запросу пользователя.

## Acceptance

A1. Изоляция двух пользователей: сферы, проекты, документы, чаты, задачи,
события, цели, поиск, задания, уведомления; прямой запрос по чужому id — 404.

A2. Онбординг: новый пользователь проходит интервью, профиль сохраняется и
виден в контексте ответа агента; можно прервать и продолжить.

A3. Документы: малый текстовый PDF → `ready` и находится; скан/книга → `queued`,
ждёт ПК, после воркера → `ready`; отмена задания работает.

A4. Агент: ответ с цитатами; уточняющий вопрос при неоднозначности; любое
изменение — только через предложение и «Применить»; агент не пишет сам.

A5. PM: подзадачи, зависимости (заблокированная не переходит в `doing`),
повторение создаёт следующий экземпляр, доска и фильтры.

A6. Календарь: событие создаётся, напоминание приходит (in-app/push),
`.ics` открывается в Apple Calendar.

A7. Развитие: цель с прогрессом, привычка с серией, метрика с графиком,
дневник, недельный обзор.

A8. Проактивность: утренний обзор и недельный отчёт приходят по расписанию;
настройка тихих часов соблюдается.

A9. Push: подписка в PWA работает; уведомление доставлено; iOS — только
установленная PWA (документировано).

A10. Ключи: сохраняются замаскированными, проверка работает, чужой ключ
недоступен; без ключа чат показывает подсказку.

A11. Яндекс.Диск: при токене оригинал > 20 МБ выгружается, документ хранит
ссылку; без токена — локально.

A12. PWA: устанавливается, офлайн открывает оболочку и последние данные.

A13. Профильные проверки: `unit-tests`, `schema-check` зелёные; новые тесты
изоляции, очереди, агентских предложений и API входят в `unit-tests`.

A14. Кастомные агенты: создаётся агент «Врач» с доступом только к сфере
«Здоровье»; его ответы и поиск не видят другие сферы; тест-запрос не пишется в
историю; сценарий запускается из чата и с «Сегодня».

A15. Многошаговый сценарий из трёх шагов выполняется последовательно,
останавливается на шаге с предложением, после «Применить» продолжается,
результат и состояние сохраняются; сценарий можно отменить.

A16. Внутренние сабагенты: «Критик» вызывается агентом «Врач» перед ответом,
его замечание учтено; сабагент не появляется в списке чатов и не создаёт
сообщений; вызов виден в трейсе (`agent_calls`). «Редактор» улучшает текст
ответа, не меняя факты и цитаты.

A17. Люди: человек создаётся с контактами, привязывается к сфере и проекту;
становится участником события и указывается в задаче с ролью; карточка
показывает связи, поиск находит по имени; второй пользователь не видит
человека и его контакты; удаление человека убирает связи.

## Этапы (внутри v1)

- **M1. Фундамент**: PostgreSQL-схема, изоляция, вход, сферы/проекты, люди
  (CRUD, привязки к сферам/проектам), PWA-оболочка.
- **M2. Знания**: загрузка, обработка (sync/очередь), воркер, поиск, аннотации,
  теги/сущности, Яндекс.Диск.
- **M3. Агент**: LLM-ключи, чат с цитатами и стримингом, tool-calling,
  предложения и кураторство, онбординг, конструктор агентов, внутренние
  сабагенты (критик/редактор), многошаговые сценарии.
- **M4. Дела**: задачи/подзадачи/зависимости/повторения, связи задач с людьми,
  календарь + ICS, участники событий, напоминания, push.
- **M5. Развитие**: цели, привычки, метрики, дневник, обзоры, проактивность,
  рекомендации, офлайн-кэш.

Каждый этап принимается отдельно: acceptance A1–A17 распределены по этапам,
задача закрывается только после зелёных проверок и независимого гейта.

## Риски

R1. Расползание v1 — много доменов. Мера: милстоуны M1–M5, приёмка по этапам.
R2. BGE-M3 на VPS 4 ГБ — swap. Мера: замер, лимит потоков, 8 ГБ или вынос
эмбеддингов на API.
R3. Изоляция ломается на новом маршруте. Мера: общий dependency `current_user`,
тесты на каждый маршрут, Qdrant-фильтр в одном месте.
R4. Агент предлагает опасное (удаление, массовое). Мера: деструктивные
предложения — только явное подтверждение, undo, audit.
R5. Утечка ключей. Мера: шифрование, маска, тесты на отсутствие в ответе/логе.
R6. Push на iOS ограничен. Мера: документировать, in-app лента как основной канал.
R7. Стриминг/отмена оставляют висящие ответы. Мера: таймаут, отмена запроса,
финальная пометка.
R8. Утечка персональных данных людей. Мера: изоляция по `owner_id`, маска в
логах, запрет индексации контактов в Qdrant, тесты на отсутствие контактов в
поиске и логах.
R9. Дубли людей из документов. Мера: только предложение о слиянии, не
автоматическое создание; карточка показывает источник упоминания.
