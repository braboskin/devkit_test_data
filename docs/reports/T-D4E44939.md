## Что сделано

M2 закрывает загрузку, обработку, очередь/воркер, поиск и Яндекс.Диск (A3, A11; FR-4, FR-5, FR-15).

- **Загрузка**: `POST /api/documents` multipart (файл или URL), лимит `ATLAS_MAX_UPLOAD_MB` (100 МБ), проверка типа, uuid-имена, хранение вне web-root, дедуп sha256 в рамках владельца, статусы `uploaded → processing/queued → ready | needs_review | failed`, URL-режим с SSRF-защитой и лимитами.
- **Fast path**: MD/TXT/DOCX и PDF ≤20 стр./≤20 МБ с текстовым слоем — извлечение, чанки, аннотация/класс/теги/сущности сразу на VPS.
- **Deferred path**: сканы/изображения/крупные PDF → job `extract`/`extract-full`; воркер ПК: токен, `claim → heartbeat → complete/fail`, скачивание оригинала, извлечение, запись текста; `scripts/worker.py`.
- **Поиск**: BGE-M3 (dense+sparse, ленивая загрузка; fake-режим для тестов) + PostgreSQL FTS (`russian`, GIN) + RRF; Qdrant-коллекция с payload `owner_id/document_id/sphere/project/ord`, payload-индексы; фильтры, `GET /api/search`, похожие документы; обязательный `owner_id` в обоих источниках.
- **Яндекс.Диск**: токен на пользователя (Fernet, маска, `min_length=20`), оригиналы >20 МБ в `/atlas/<user_id>/<document_id>.<ext>`, локальная копия сохраняется для `/file`/`reprocess`, удаление чистит облако и локальную копию; без токена — локально.
- **Knowledge core**: `app/backend/knowledge/**` — extract (PDF/OCR/DOCX/MD), chunking, triage, entities, annotate, pipeline; `scripts/*` — тонкие CLI-обёртки (прежние тесты зелёные).
- **Viewer**: вкладки «Документы» (upload/список/карточка/поиск/похожие/переобработка/удаление), «Поиск», «Задания» (очередь, отмена, worker-token), «Настройки» (Яндекс.Диск).
- **Интеграция**: авто-подключение роутеров в `main.py`; фиксы по ревью: F4/F5 (yandex-оригиналы/удаление), F2 (лимиты URL), F3 (`Content-Length`), F6 (маска токена), F10 (reprocess guard), worker `/file` для yandex.

## Риски

- **Реальная BGE-M3 и Qdrant-сервер** не проверялись (решение владельца): тесты на
  in-memory Qdrant + fake-эмбеддингах; реальная семантика — ручная приёмка.
- **Яндекс.Диск** — mock; реальный токен/сеть — ручная приёмка A11. Скачивание из
  облака при отсутствии локальной копии не реализовано (409, follow-up).
- **SSRF DNS-rebinding** (TOCTOU между проверкой и `httpx.stream`) — major-risk
  без эксплуатации; нужна аутентификация. Follow-up: pinned resolver/коннект по IP.
- **Chunked-тело** без `Content-Length` ограничивается после парсинга (второй
  рубеж `save_stream`); follow-up — нативный `max_body_size` (проверен вручную).
- **Гонка дедупа** двух параллельных загрузок одного файла → 500 по unique
  (follow-up: ловить `IntegrityError`).
- **`_hook`-индексация** глотает ошибку Qdrant (warning): документ `ready`, но
  может не находиться поиском; architecture follow-up — прямой импорт/ретрай.
- Сырой текст ошибок извлечения в `document.error` (без секретов/путей —
  ограничить, follow-up).
- `tests/test_web_build` скипается, если `viewer/dist` не собран (web-build
  ловит отдельно); SQLite-claim не проверяет конкурентный `SKIP LOCKED` на PG.
- `.gitignore` (`inbox/`) игнорирует `tests/fixtures/inbox`; фикстуры добавлены
  через `git add -f`, отслеживаются. Правка `.gitignore` отложена (CRLF-churn).
- Оригиналы >20 МБ остаются локально (для `/file`/`reprocess`), даже при
  выгрузке в облако; удаление документа чистит обе копии.
