# Отчёт T-59D31937 — роутинг: SPA-fallback и страница 404

## Что сделано

Починен корень бага «любая страница кроме главной даёт ошибку»: `StaticFiles`,
смонтированный на `/`, отвечал 404 JSON на любой неизвестный путь, поэтому
deep link (`/settings`, `/chat/1`, `/nope`) умирал на собранном фронте. Теперь
неизвестные пути вне `/api/**` и `/health` отдают SPA-оболочку, API-404 остаются
JSON. Неизвестный маршрут внутри приложения показывает страницу 404 в оболочке
вместо молчаливого редиректа на `/`.

- A8: `/settings`, `/chat/1`, `/nope` → 200 HTML с корнем SPA; `/api/nope` →
  404 JSON; `/health` → 200 JSON. Доказано `tests/test_spa_fallback.py`
  (5 тестов) и e2e `not-found.spec.ts`.
- Легаси-редиректы (`today`, `documents`, `interests`) сохранены.
- 404 — antd `Result` с иконкой Lucide в цветах темы, путь в `<code>`, кнопка
  «На главную»; рендерится внутри `AppShell`.
- `Result` добавлен в публичный API `shared/ui` — страница не импортирует antd
  напрямую (`AGENTS.md`).

## Изменения

**Бэкенд:** `app/backend/main.py` — `SPAStaticFiles(StaticFiles)` с fallback на
`index.html`; проверка API-префикса сегментная и с нормализацией разделителей,
потому что `StaticFiles` на Windows отдаёт путь как `api\nope` (ловушка найдена
тестом: первая версия пропускала `/api/nope` в SPA).
`tests/test_spa_fallback.py` — новый, 5 тестов, скипается без сборки.

**Фронтенд:** слайс `pages/not-found` (`index.ts` + `ui/NotFound.tsx`),
`router.tsx` — wildcard → `<NotFound />`; `e2e/not-found.spec.ts`.
`shared/ui/surface.tsx` + `index.tsx` — обёртка `Result` в публичном API.
`shared/ui/controls.tsx` — варианты `Button` на токенах с двойной
специфичностью: legacy `base.css` объявляет `button[type='button']` (0,1,1) и
перекрашивал antd-кнопки в светлый, текст становился светлым на светлом
(нашлось на 404). Правится до удаления legacy-слоя в T-7E446096.

**Коммиты (ветка `devkit/T-59D31937`):**

- `5e88f31` feat(web): страница 404 в оболочке и Result в public API
- `95f3368` fix(backend): SPA-fallback для deep link, JSON 404 для /api и /health

Отклонения: `Result` рендерится без `status="404"`, потому что antd при
известном статусе игнорирует `icon` и подставляет свою цветную иллюстрацию —
вместо неё иконка Lucide в цветах темы. План этого не запрещал, но фиксирую.

## Риски

1. **Ассеты с расширением** (`/assets/missing.js`) теперь получают оболочку
   (200 HTML), а не 404 — следствие правила «неизвестный путь → SPA». Если нужен
   строгий 404 для ассетов, это отдельное решение.
2. **Не-GET методы** (`POST /settings`) пробрасываются как есть (405) —
   поведение `StaticFiles` не менялось, тестом не покрыто.
3. **Legacy `base.css`** продолжает перекрашивать нативные `<button>` в
   экранах, ещё не переведённых на примитивы; shared `Button` уже защищён
   двойной специфичностью, но экранные задачи должны перевести свои кнопки.
4. **e2e требует собранного `dist`** — при ручных прогонах без `npm run build`
   тесты идут против старой сборки.
