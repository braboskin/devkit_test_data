## Риски

- **F8 (контракт):** worker `fail` больше не принимает произвольный текст — только
  категорию из allowlist (неизвестное → `extract_failed`); старым клиентам воркера
  нужно слать категорию.
- **reset-password** удаляет worker-tokens и `Integration` (включая Yandex);
  облачные оригиналы в `/atlas/<owner>` при этом не удаляются (токен уже отозван) —
  возможны «сироты» до переподключения OAuth.
- **F12 lease:** «зависшие» running-задания перехватываются через
  `ATLAS_WORKER_LEASE_MINUTES` (default 30), после 3 попыток → `failed`;
  heartbeat продлевает `started_at`, `attempts` — generation (старый воркер
  получает 409). Heartbeat-поток при сетевом сбое молча выходит — задание
  завершится по lease/complete.
- **H2:** `tests.test_followup_acceptance` добавлен в `unit-tests` профиля.
- **H1:** callback при неверном state отдаёт 303 `/?yadisk=error` (UX), а не 400
  из брифа; обмен code не выполняется — принято как контракт.
- **F11 live** не проверен: нужны `YANDEX_CLIENT_ID/SECRET/REDIRECT_URI` и
  Redirect URI в приложении Яндекса; тесты — mock.
- **F1:** SNI/TLS проверены на fake-stream/httpcore; реальный handshake/сертификат
  не гонялся; NAT64/`::/96` закрыты deny-list.
- Миграция 0003 создаёт partial unique index только в Alembic; в
  `models.Base.metadata` индекс не объявлен — возможен drift при autogenerate
  (follow-up: добавить `Index(...)` в `models.py`).
- `--concurrency` при одном worker-токене и single-flight даёт мало выигрыша;
  польза — разные владельцы/процессы.
- Реальные BGE-M3/Qdrant — принятое ограничение (owner decision).
- `_drop_index` при удалении по-прежнему не валит запрос при сбое Qdrant
  (только лог) — возможны stale-точки.
- UI проверен сборкой/smoke, не браузерным E2E.
